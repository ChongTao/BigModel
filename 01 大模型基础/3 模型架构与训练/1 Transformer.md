# Transformer

Transformer 是现代大语言模型最核心的底层架构之一。它由 Google 团队在 2017 年的论文 [Attention Is All You Need](https://arxiv.org/abs/1706.03762) 中提出。Transformer解决的是：**模型内部到底用什么结构完成这些计算。**

## 1. Transformer 的核心思想

Transformer 的核心思想是：

**通过注意力机制直接计算序列中不同位置的信息关系，并支持并行计算多个位置的表示。**

这种并行性主要体现在训练和处理完整输入时；自回归模型生成时仍按 Token 逐步输出。

这带来三个关键收益：

- 更容易并行训练
- 更擅长建模长距离依赖
- 更容易扩展到超大参数规模

## 2. Transformer 结构图

![](https://www.runoob.com/wp-content/uploads/2025/06/Transformer_full_architecture.png)

上图展示的是 **2017 原始论文中的经典 Encoder-Decoder Transformer**。从这个经典结构看，Transformer 主要包含：

1. 输入处理：把 token 转成向量，并加入位置信息
2. 编码器（Encoder）
3. 解码器（Decoder）
4. 输出层：把内部表示映射回词表概率

但要注意：**“Transformer”是一个架构家族，不等于必须同时有 Encoder 和 Decoder。**

## 3. 编码器与解码器

### 3.1 编码器

编码器的作用是：对输入序列做上下文化理解。

常见组成包括：

- Multi-Head Self-Attention
- Feed-Forward Network
- Residual Connection
- LayerNorm

编码器适合理解任务，因此很多理解型模型会偏向 Encoder-Only 结构。

### 3.2 解码器

解码器的作用是：根据已有上下文一步步生成后续内容。

它和编码器的重要差异在于：

- 解码器会使用因果掩码（causal mask）
- 当前 token 只能看到自己之前的内容，不能看到未来

这保证了生成过程符合“从前到后逐步生成”的方式。

### 3.3 三种结构的特点与适用场景

| 结构 | 信息流与训练方式 | 适用场景 | 代表模型 |
| --- | --- | --- | --- |
| Encoder-only | 双向读取输入各位置，常通过掩码预测或任务头学习上下文化表示 | 分类、实体识别和文本表示；标准结构没有因果解码路径，通常不直接用于开放式逐 Token 生成 | BERT |
| Decoder-only | 使用因果掩码，只读取当前位置及之前的 Token，常以预测下一 Token 训练 | 对话、写作、代码和问答等可统一建模为续写的生成任务 | GPT、Llama、Qwen |
| Encoder-Decoder | Encoder 编码输入，Decoder 通过交叉注意力读取编码结果并生成输出 | 翻译、摘要等输入输出边界清楚的转换任务 | 原始 Transformer、T5 |

通用 LLM 大多采用 Decoder-only，因为下一 Token 预测能统一文本、对话和代码等生成目标，结构也便于规模化训练。这个趋势不代表它对所有任务都更合适；选型仍需按目标数据比较质量、延迟和成本。

## 4. Self-Attention

Self-Attention 是 Transformer 的核心。它要解决的问题是：

**当前 Token 在更新自己表示时，应该重点参考上下文中的哪些 Token。**

例如在句子：

```text
苹果发布了新手机，它的芯片性能更强
```

模型在处理“它”时，应该更关注“苹果”或“新手机”，而不是平均看待所有词。

这就是注意力机制的意义：对上下文做有重点的加权读取。

### 4.1 相似度为什么要缩放

`Q` 与 `K` 的点积数值尺度会随向量维度 `d_k` 增大。除以 `√d_k` 可以稳定 softmax 的输入范围，减少权重过度集中和梯度变小的问题。

因此标准做法是先按维度缩放，再送入 softmax：

```text
Attention(Q, K, V) = softmax(QK^T / √d_k) · V
```

这个公式同时指出了注意力开销的来源：`QK^T` 需要算出序列中每一对位置之间的相似度，计算量随长度平方增长。

## 5. Q、K、V 怎么理解

Q、K、V 是注意力层从隐藏表示中计算出的三组向量。可以把它们的分工记成“查询、匹配、内容”：

| 向量 | 全称 | 在注意力中的作用 |
| --- | --- | --- |
| `Q` | Query，查询 | 表示当前位置在计算这一层输出时要用什么特征寻找相关信息 |
| `K` | Key，键 | 提供与查询比较的特征，用来计算每个位置与当前位置的匹配分数 |
| `V` | Value，值 | 提供真正参与加权汇总的内容向量 |

“查询”与“键值”是帮助理解的比喻。它们不是人工写入的标签，也不保证某个维度有固定的词义；投影方式由训练得到。

### 5.1 Q、K、V 从哪里来

设一段输入经过 Embedding 和前序层后得到隐藏表示矩阵 `X`，每一行对应一个位置的向量。注意力层使用三组不同的可学习权重，把同一批隐藏表示投影到三个空间：

```text
Q = X W_Q
K = X W_K
V = X W_V
```

对第 `i` 个位置，可以写成 `q_i = h_i W_Q`、`k_i = h_i W_K`、`v_i = h_i W_V`。因此，同一个位置会同时产生自己的 `Q`、`K` 和 `V`；当前位置的 `Q` 会与可见位置的 `K` 比较，再用计算出的权重汇总相应的 `V`。

若隐藏维度是 `d_model`，单个注意力头通常把 `Q`、`K` 投影到 `d_k` 维，把 `V` 投影到 `d_v` 维：

| 张量 | 常见形状（不含批次维） | 用途 |
| --- | --- | --- |
| `X` | `[L, d_model]` | 长度为 `L` 的输入隐藏表示 |
| `Q` | `[L_q, d_k]` | 查询位置的表示 |
| `K` | `[L_k, d_k]` | 可供查询匹配的位置表示 |
| `V` | `[L_k, d_v]` | 与 `K` 对齐、可被汇总的内容表示 |

这里 `L_q` 是查询位置数，`L_k` 是键值位置数。自注意力中两者通常相同；交叉注意力中，查询序列和键值序列可以不同。实际框架可能把三组投影合并成一次矩阵运算以提高效率，但计算含义不变。

在批处理的多头注意力中，投影结果通常会拆成多个头，形状可写成 `Q: [B, H_q, L_q, d_k]`、`K: [B, H_kv, L_k, d_k]`、`V: [B, H_kv, L_k, d_v]`。注意力分数的形状是 `[B, H_q, L_q, L_k]`。MHA 中 `H_q = H_kv`；GQA 和 MQA 则让多个查询头共享较少的 K/V 头，以减少 KV Cache。

### 5.2 从匹配分数到加权汇总

对于第 `i` 个查询位置和第 `j` 个键值位置，先计算点积并按 `√d_k` 缩放：

```text
s_ij = (q_i · k_j) / √d_k + m_ij
```

`m_ij` 是掩码项；允许关注的位置通常加 `0`，需要屏蔽的位置加 `-∞`。随后在每个查询对应的所有键位置上做 softmax，得到注意力权重：

```text
α_ij = softmax_j(s_ij)
```

最后按这些权重汇总 Value 向量，得到当前位置的注意力输出：

```text
z_i = Σ_j α_ij v_j
```

把所有位置合在一起，就是缩放点积注意力：

```text
Attention(Q, K, V) = softmax((Q K^T) / √d_k + M) V
```

`Q K^T` 的结果是匹配分数矩阵，行对应查询位置，列对应键位置；softmax 把每一行转换为在可见位置上的权重分布。`Q` 和 `K` 决定读取哪些位置、各占多少权重，`V` 决定汇总进输出的内容。点积本身还不是概率，softmax 后才是权重。

### 5.3 一个直观例子

在“**小猫追着球跑，因为它滚到了沙发下**”这句话中，处理“它”时，当前位置的隐藏表示会生成一个 `Q`。它与可见上下文中各位置的 `K` 计算分数，再按权重汇总这些位置的 `V`。这个例子里，“球”可能提供有用信息，因为后文描述“滚到了沙发下”。实际模型处理的是向量表示，注意力权重也不等同于人类可读的词语重要性判断；模型可以结合多层、多头和其他上下文特征完成推断。

### 5.4 自注意力与交叉注意力

- **自注意力（Self-Attention）**：`Q`、`K`、`V` 都由同一组输入隐藏表示 `X` 投影得到。Decoder-only LLM 的标准注意力层通常属于带因果掩码的自注意力。
- **交叉注意力（Cross-Attention）**：`Q` 来自当前解码序列，`K` 和 `V` 来自另一组表示，例如 Encoder 的输出。这样，解码位置可以根据自己的查询读取源序列的信息。

二者使用相同的匹配和加权汇总公式，区别在于 `Q` 与 `K`、`V` 的来源是否相同。

### 5.5 因果掩码与 KV Cache

自回归 Decoder 在位置 `i` 只能读取位置 `i` 及之前的内容。因果掩码会在 softmax 之前屏蔽所有 `j > i` 的分数；被屏蔽的位置权重为 `0`。Padding mask 则用于屏蔽批处理中补齐出来的位置，两种掩码解决的问题不同。

逐 Token 解码时，新位置生成自己的 `q`、`k`、`v`：`q` 与历史及当前的 `K` 匹配，再按权重汇总相应的 `V`。模型会缓存已经计算过的历史 `K`、`V`，避免每生成一个 Token 都重新投影整段历史；这就是 KV Cache 的基本用途，细节见第 10.3 节。

对每个查询而言，softmax 会在未被掩码的位置上把权重归一化为 1，因此可以把注意力理解为可见位置间的加权分配。不过，增加上下文长度不会必然降低某个特定 Token 的权重；权重取决于各位置的点积和掩码。长上下文的信息利用还与模型训练分布、位置处理、信息所在位置和提示设计等因素有关。

## 6. Multi-Head Attention

Transformer 不只用一个注意力头，而是会同时使用多个头并行关注不同模式。

这样做的原因是：

- 各头通过独立的投影矩阵并行处理不同的表示子空间。
- 多个头的结果可以组合不同的关联信息。

各头算出的结果会先拼接，再经过一次输出投影（`W_O`）融合成本层的最终输出。没有 `W_O` 时，当前注意力层只会并列拼接各头表示，无法在该层通过线性投影混合不同头的通道；后续层仍可继续处理这些特征。

训练后，有些头可能对某些模式更敏感，但每个头与某种语义功能之间没有固定的一一对应关系，也可能存在冗余。例如：

- 某些头对语法依赖更敏感
- 某些头对指代关系更敏感
- 某些头对远距离信息更敏感

这也是 Transformer 表达能力强的重要原因之一。

### 6.1 注意力中的 K/V 组织方式

多头注意力可按查询头与 K/V 头的共享关系区分。减少 K/V 头数通常可以缩小 KV Cache，但具体收益还取决于头维度、上下文长度和实现方式。

| 方式 | K/V 组织 | 主要特点 |
| --- | --- | --- |
| MHA | 每个查询头有对应的 K/V 头 | K/V 头数随查询头数增加，缓存开销相对较大 |
| MQA | 所有查询头共享一组 K/V 头 | K/V 头数最少，缓存需求较低 |
| GQA | 一组查询头共享一组 K/V 头 | 在 MHA 与 MQA 之间折中 |
| MLA | 将 K/V 信息压缩到低维潜在表示 | 通过潜在表示压缩缓存，机制不同于按头共享 |

这些方式属于注意力层的设计选项，不能单凭名称判断模型质量或推理速度。

## 7. Transformer 的关键组件

可以按三个位置来区分：

- 输入侧：Token Embedding，把 Token ID 查表成向量
- 位置信息：可加到 Token 表示中，也可在注意力计算中注入
- 层内部：Attention 与 Feed Forward 两个子层，以及包裹在每个子层外的残差连接和归一化

Token Embedding 通常在输入侧查表得到；位置机制的作用位置取决于具体方案。绝对位置编码常加到 Token 表示中，RoPE 则在注意力计算中作用于 Q/K。“堆很多层”的是后面的 Transformer block。

一个标准 Transformer 层由两个子层堆成，每个子层都被残差连接和归一化包裹：

- Multi-Head Attention：有重点地读取上下文，负责在位置之间搬运信息
- Feed Forward Network：对每个位置独立做非线性变换，负责就地加工信息
- Residual Connection：把子层输入直接加回输出，保留原始信息，避免深层退化
- 归一化（LayerNorm / RMSNorm）：稳定数值分布，让深层网络可训练

可以把它理解成：每一层都让 Token “重新看一遍上下文”，然后把自己的表示更新得更准确。

### 7.1 残差流视角

把各层的残差连接串起来看，可以把整个模型理解为一条贯穿所有层的**残差流**：每层的注意力和 FFN 都从这条流上读取信息，再把计算结果加回去。

这个视角能解释两件事：

- 残差连接提供直接传递子层输入的路径，子层可以在已有表示上叠加更新
- 信息因此有机会跨层传播，但并不保证某个特征一定保留；后续层仍可能改变或削弱它

### 7.2 归一化放在哪里：Pre-LN 与 Post-LN

2017 年原论文把归一化放在子层输出之后（Post-LN）。许多现代 Decoder-only LLM 把归一化放在子层输入之前（Pre-LN），并使用 RMSNorm；具体结构仍随模型而异。

差别在于：

- Post-LN 在深层网络中可能更难稳定训练，训练时常需配合预热等策略
- Pre-LN 在子层前归一化，为残差流保留近似恒等的直通路径，有助于深层网络的梯度传播
- RMSNorm 去掉 LayerNorm 的均值中心化，只做尺度归一；它在许多模型中效果良好，但不代表对所有配置都等价

### 7.3 Feed Forward 层承担什么

FFN 常被一句话带过成“非线性变换”，但它的分量远比这大：

- 参数占比高：在常见 Dense Transformer 配置中，FFN 约占单层参数量的三分之二；实际比例取决于注意力和 FFN 的维度设计
- 计算逐位置独立：每个 Token 各自经过同一组权重，不涉及跨位置交互
- 一种研究视角把 FFN 描述为键值记忆，以“模式匹配 → 写出对应内容”解释它如何存储和调用部分关联

键值记忆是解释 FFN 的一种研究视角，不代表事实知识只存储在 FFN。提示词可以通过上下文提供新事实；微调能改变参数及模型行为，但不保证模型准确记住事实。需要持续更新或引用来源的知识通常更适合结合 RAG。

### 7.4 MoE：按 Token 路由的专家 FFN

Dense Transformer 通常让每个 Token 经过相同的 FFN 参数。MoE（Mixture of Experts）会在部分层放入多个专家 FFN，由路由器为每个 Token 选择 Top-k 专家参与计算，因此全模型权重总量可以大于单个 Token 实际激活的参数量。

比较 MoE 时要分别看**总参数**和**激活参数**：总参数影响权重存储需求，激活参数可粗略反映单 Token 的计算规模；两者都不能单独预测服务速度或整体显存。路由均衡、批量大小、跨设备通信、权重精度和运行时实现都会影响效果，MoE 不保证在所有场景下都比 Dense 更快或更便宜。多种架构的组合见[2 模型架构谱系](2%20%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E8%B0%B1%E7%B3%BB.md)，推理侧资源影响见[推理工程概述](../../04%20%E6%8E%A8%E7%90%86%E4%B8%8E%E9%83%A8%E7%BD%B2/%E6%8E%A8%E7%90%86%E5%B7%A5%E7%A8%8B/01%20%E6%8E%A8%E7%90%86%E5%B7%A5%E7%A8%8B%E6%A6%82%E8%BF%B0.md)。

## 8. 参数量都花在哪

把参数拆开看，有助于理解模型规模、词表和显存之间的关系：

| 部分 | 规模量级 | 说明 |
| --- | --- | --- |
| 输入 Embedding | 词表大小 × 隐藏维度 | 词表越大占用越多；中文和多语言模型的词表通常更大 |
| N 个 Transformer 层 | 每层约 12 × 隐藏维度的平方 | 注意力约占 4 倍、FFN 约占 8 倍；层数和隐藏维度是主要放大项 |
| 输出投影 | 隐藏维度 × 词表大小 | 部分模型与输入 Embedding 共享权重（weight tying），部分不共享 |

由此可以得到几个结论：

- 参数量主要由层数、隐藏维度和词表大小决定，与上下文长度无关。
- 上下文长度影响的是运行时的激活值和 KV Cache 显存，不是权重体积。
- 因此“同一个模型支持更长上下文”通常不需要更多权重显存，却需要更多运行时显存。

## 9. 隐藏表示如何变成输出

Self-Attention 和 Transformer 层处理出来的，首先不是最终答案，而是一串更丰富的**隐藏表示（hidden states）**。

在生成任务里，后面通常还会接：

1. 线性映射：把隐藏表示投影到词表大小
2. softmax：得到“下一个 token 的概率分布”
3. 采样或贪心选择：真正选出要输出的 token

所以可以把链路理解成：

`token -> embedding -> transformer layers -> hidden states -> vocab logits -> 概率分布 -> 输出 token`

这也说明：

- Attention 更新的是表示，不是直接“选词”
- 真正变成输出 token，还要经过输出层和采样步骤

## 10. 计算代价与 KV Cache

### 10.1 注意力是平方复杂度

序列长度为 `n`、隐藏维度为 `d` 时，标准全注意力的主要计算量约为 `O(n²d)`，逐 Token 的 FFN 计算量随 `n` 线性增长：

- 显式构造完整注意力分数矩阵的实现，需要 `O(n²)` 的额外矩阵空间；FlashAttention 等内核可避免物化该矩阵，但不会消除全注意力的平方计算量

因此，常见模型的短序列计算可能主要花在 FFN 和投影上；序列变长后，注意力的平方项会快速增加。实际瓶颈还取决于模型维度、注意力内核和硬件。

### 10.2 Prefill 与 Decode 是两个阶段

自回归生成的一次请求分成两个特性完全不同的阶段：

| 阶段 | 做什么 | 计算特性 |
| --- | --- | --- |
| Prefill | 并行处理输入 Token，计算各层的 K、V，并由最终 logits 选出首个生成 Token | 可并行，通常计算密集 |
| Decode | 每步处理一个新 Token，并复用此前缓存的 K、V 来生成后续 Token | 自回归串行，常受访存影响 |

这解释了为什么服务端会分别观察首 Token 延迟（TTFT）和每 Token 延迟（TPOT）：模型计算阶段不同，但端到端延迟也受排队、网络和服务调度影响。
### 10.3 KV Cache 从哪来

Decode 阶段每生成一个 Token，都要用新的 `Q` 和**此前可见位置**的 `K`、`V` 做注意力。如果每步都重算历史位置的 `K`、`V`，计算量会随长度反复膨胀。

因此推理引擎会把已算出的 `K`、`V` 缓存下来，这就是 KV Cache。其存储量大致随层数、Token 数、KV 头数、头维度、每个值的字节数和活动序列数线性增长；前缀共享等机制可以复用部分缓存。长上下文或高并发时，KV Cache 会占用显著显存，但是否超过模型权重取决于模型、并行方式和缓存精度。

Decode 每步都要读取相关 KV Cache，因此许多服务负载会受到显存带宽影响；实际瓶颈会随批量大小、硬件和内核变化。

## 11. 位置信息与上下文长度

注意力本身不区分顺序：打乱输入 Token，算出的注意力关系不会变。位置信息必须额外注入，否则模型无法理解语序。

### 11.1 位置编码的演进

| 方案 | 做法 | 特点 |
| --- | --- | --- |
| 正弦绝对位置编码 | 用不同频率的三角函数生成位置向量，加到 Token 表示上 | 原论文方案，无参数；外推到训练长度之外效果有限 |
| 可学习绝对位置编码 | 每个位置对应一个可训练向量 | 早期 BERT、GPT 采用；位置数固定，超出即无法处理 |
| 相对位置编码 | 直接建模两个位置之间的距离 | 对长度变化更鲁棒 |
| RoPE | 在注意力计算中对 Q、K 做与位置相关的旋转 | 当前主流；相对位置关系自然体现在点积结果里 |
| ALiBi | 按位置距离给注意力分数加线性惩罚 | 不改动权重，倾向于关注近距离内容 |

### 11.2 上下文长度上限从哪来

模型能处理多长的上下文，不由单一因素决定：

- 位置编码的表示范围，以及是否做过长度外推训练（位置插值、NTK 缩放、YaRN 等）
- 训练语料里长序列的覆盖程度
- 运行时的 KV Cache 显存和注意力计算开销
- 在目标长度上的实际检索与推理表现

前两条决定模型“能不能”，第三条决定服务“划不划算”，最后一条决定“好不好用”。

## 12. Transformer 解决了什么问题

和它取代的 RNN / LSTM 相比，关键差别在信息传递方式：

| 维度 | RNN / LSTM | Transformer |
| --- | --- | --- |
| 处理方式 | 按时间步串行，逐步更新隐状态 | 一次算出所有位置之间的关系 |
| 长距离依赖 | 信息需经多步传递，容易衰减 | 任意两个位置直接相连，路径长度为 1 |
| 并行度 | 受时间步限制，难以充分利用 GPU | 训练时可整序列并行 |
| 扩展性 | 加深加宽收益有限 | 参数、数据、计算同步扩展时收益明显 |

代价是失去了 RNN 那种固定大小的隐状态：Transformer 必须显式保存全部历史，这正是 KV Cache 的来源。

现代大语言模型、视觉 Transformer 和多模态模型，大多建立在 Transformer 或其变体之上。

## 13. Transformer 的局限

优势的另一面就是约束，这些约束直接决定了推理系统的形态：

- **平方复杂度**：标准全注意力的计算开销随长度平方增长；超长序列的成本还取决于注意力内核和硬件。
- **状态随长度增长**：KV Cache 让显存占用与序列长度、并发数成正比，限制单卡能服务的请求数。
- **位置外推有限**：超出训练长度的位置区间后质量往往明显下降，需要专门的外推方法和长文评测验证。
- **Decode 阶段常受访存影响**：每步只生成一个 Token，KV Cache 读取可能成为瓶颈；具体表现取决于批量、硬件和实现。

这些局限催生了两类应对：一是在 Transformer 内部继续优化（GQA、MLA、FlashAttention、稀疏注意力、连续批处理），二是换用或混合其他序列建模骨干（SSM、循环式架构）。
