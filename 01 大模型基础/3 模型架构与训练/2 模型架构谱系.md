# 模型架构谱系

## 1. 架构维度与组合关系

| 维度 | 常见选择 | 回答的问题 |
| --- | --- | --- |
| 序列建模骨干 | 全注意力 Transformer、状态空间模型（SSM）、线性注意力、Retention、循环式与混合架构 | 序列信息如何建模和传递 |
| Transformer 信息流 | Encoder-only、Decoder-only、Encoder-Decoder | 输入如何编码、输出如何生成 |
| 参数激活与路由 | Dense、Mixture of Experts（MoE） | 每个 Token 会经过哪些参数 |
| 注意力中的 K/V 组织 | MHA、MQA、GQA、MLA | K/V 头或表示如何组织 |
| 模态与融合 | 文本、图像、音频、视频及组合 | 模型接收和生成什么类型的信息 |

这些维度分别描述不同结构选择。例如，一个模型可以同时采用 Decoder-only 信息流、MoE 路由和 GQA；多模态标签则描述输入或输出类型。单个标签不能概括完整架构，具体配置应以模型卡、技术报告和服务文档为准。

## 2. 序列建模骨干

| 路线 | 信息传递方式 | 代表与特点 |
| --- | --- | --- |
| 全注意力 Transformer | 在可见位置之间直接计算注意力关系 | 可灵活读取上下文；标准全注意力的注意力计算量随序列长度平方增长 |
| 状态空间模型（SSM） | 通过状态递推聚合序列信息 | Mamba 是代表；Mamba-2 研究了 SSM 与注意力之间的数学联系，但两者并不因此成为相同机制 |
| 线性注意力 | 通过核近似或状态累积等方式改写注意力计算 | 某些方法可避免显式计算完整的位置两两关系；具体复杂度和效果取决于方法 |
| Retention | 通过带衰减的保留机制聚合历史信息，可采用并行、分块或递推计算形式 | RetNet 是代表；与线性注意力相关，但机制并不相同 |
| 循环式架构 | 逐步更新有限状态并传给下一个位置 | RWKV 是代表之一；生成过程按序列递推 |
| 混合架构 | 在同一模型中组合注意力层与其他序列模块 | Jamba 组合了 Transformer 与 Mamba 模块；缓存和计算取决于具体层设计 |

许多 SSM 和循环式模型在增量推理时维护不随上下文长度持续增长的状态；全注意力自回归解码通常需要随上下文增长的 KV Cache，混合模型的开销取决于各层组成。有限状态是对历史的压缩表示，不能保证保留任意历史细节；应按目标任务评测质量和资源开销。

## 3. 参数激活方式：Dense 与 MoE

Dense 与 MoE 描述每个 Token 激活参数的方式，可以和不同序列骨干组合；实际组合方式取决于具体模型设计。

| 方式 | 每个 Token 的计算 | 主要权衡 |
| --- | --- | --- |
| Dense | 每个 Token 经过相同的主要网络参数 | 计算路径直接；扩大模型通常会增加每 Token 的计算量 |
| MoE | 路由器按 Token 选择部分专家参与计算 | 总参数量可以大于单个 Token 的激活参数量；专家路由和跨设备通信会增加实现复杂度 |


## 4. 多模态模型

多模态模型的输入和输出模态可以不同。常见的信息融合方式包括以下几类；实际模型可能组合使用：

| 方式 | 基本做法 | 公开实例 |
| --- | --- | --- |
| 编码器加投影层 | 单独编码图像等输入，再把特征映射到语言模型的表示空间 | LLaVA（图像） |
| 交叉注意力 | 语言模型在生成时通过交叉注意力读取编码后的其他模态特征 | Flamingo（图像） |
| 统一多模态 Token 序列 | 把不同模态编码为可混排的 Token，放入统一序列中建模 | Chameleon、Emu3 |

融合方式本身不能决定模型是否会生成图像或音频；输出能力还取决于相应的解码器、输出头和训练数据。图像、音频和视频在模型内部可能表示为 Patch、连续特征或专用 Token，具体上下文预算和计费规则要查模型及服务文档。
