# 01 采样与解码

大语言模型按自回归方式逐步生成内容：每一步根据已有上下文，为词表中的 Token 计算一组分数，再决定下一个 Token。这里的 Token 是模型处理的文本片段或特殊标记，不一定对应一个完整的词。

- **解码（decoding）**：从模型给出的候选分布中选择 Token、扩展候选序列，并决定何时停止的过程。
- **采样（sampling）**：解码的一种方式，按概率随机抽取下一个 Token。

因此，贪心解码和束搜索属于解码，但通常不称为采样；Top-k、Top-p 和 Min-p 则是常见的采样过滤方法。

## 1.1 从 logits 到下一个 Token

模型输出层给出词表中各 Token 的 logits（未归一化分数）。经过 softmax 后，logits 才变为概率。生成系统还可以调整这些分数、屏蔽不允许的候选，再按贪心、采样或搜索策略选出 Token。

可以把一轮生成抽象为：

`上下文 -> logits -> 约束与分数调整 -> 概率变换与候选过滤 -> 重新归一化 -> 选择 Token -> 追加到上下文`

这条链路是概念模型。不同模型、API 和推理引擎可能采用不同的处理顺序，也可能不开放全部控制项；组合参数时应以目标实现的文档为准。

## 1.2 常见的解码策略

| 策略 | 如何选择 | 特点与常见用途 |
| --- | --- | --- |
| 贪心解码（greedy） | 每一步选当前分数最高的可用 Token | 计算开销低，选择过程直接；只看当前一步，长文本可能重复或错过更好的后续序列。 |
| 概率采样（multinomial sampling） | 按处理后的概率分布随机抽取 Token | 同一输入可以产生不同续写；开放式生成常用，结果会随随机种子和运行环境变化。 |
| 束搜索（beam search） | 同时保留多条部分序列，按累积序列分数扩展和筛选 | 适合翻译、语音识别等输入约束较强的序列任务；束宽有限，且长度归一化等评分规则会影响排序，不保证找到全局最优序列。 |

束搜索常用累积 log 概率为候选序列打分，有些实现还会使用长度惩罚或其他归一化。部分框架也允许把束搜索与随机采样结合，具体名称和行为以框架文档为准。

## 1.3 温度与候选过滤

温度和 Top-k、Top-p、Min-p 会改变每一步实际参与选择的分布。过滤候选后，保留项的概率会重新归一化，再用于抽样。设第 `i` 个 Token 的 logit 为 `z_i`，温度为正数 `T` 时，一种常见的温度变换是：

`p_i = softmax(z_i / T)`

- `T = 1` 不因温度改变分布。
- `0 < T < 1` 会放大分数差异，使分布更尖锐。
- `T > 1` 会缩小分数差异，使分布更平坦。

候选过滤方法的区别如下：

| 方法 | 保留规则 | 直观理解 |
| --- | --- | --- |
| Top-k | 只保留分数最高的 `k` 个候选 | 候选数量固定，分布变化时适应性有限。 |
| Top-p（nucleus sampling） | 按概率从高到低排列，保留累计概率达到 `p` 所需的最小候选集合 | 候选数量会随分布变化；它并不天然比 Top-k 生成得更自然或更准确。 |
| Min-p | 通常保留概率不低于最高候选概率乘以 `min_p` 的 Token | 阈值相对最高概率计算；与 Top-p 的累计概率规则不同。 |
| Typical、epsilon、eta 等 | 按局部典型性或概率阈值进一步筛选 | 一些推理库提供这些方法，定义和支持范围并不统一。 |

温度会影响后续概率，而 Top-p、Min-p 也会据此改变候选集合；同时启用多个过滤器可能让候选缩到很少。频率惩罚、重复惩罚和 logit bias 则会按已生成内容或指定偏置修改分数，具体公式及作用范围因实现而异。参数定义和接口差异见[生成参数与结构化输出](02%20生成参数与结构化输出.md)。

## 1.4 受约束解码与停止条件

受约束解码（constrained decoding）会利用 JSON Schema、语法或其他规则，屏蔽不符合约束的后续 Token。运行时支持严格约束时，它可以提高结构和语法的合规性；但合法 JSON 不代表字段值正确，语法正确也不代表内容真实，解析后仍需做业务校验。

停止条件与 Token 选择是两个不同环节：模型生成结束标记、达到最大输出长度，或命中 API 定义的停止字符串时，系统会结束生成。停止规则的匹配方式和返回内容也可能因 API 而异。

## 1.5 配置与复现

不同模型和服务支持的采样参数不一样，默认值、取值范围和参数组合也可能不同。推理模型或托管 API 还可能限制部分参数；应先查目标模型及服务的说明，不要把某套参数当成跨模型通用配方。

- `temperature = 0` 不是 softmax 公式中的有效温度值。某些 API 会把它特殊处理为贪心选择，另一些实现可能拒绝该值；应按对应文档理解。
- 降低温度只改变候选选择方式，不会补充模型缺少的事实知识，也不能保证回答正确。
- 如果接口支持随机种子（seed），它有助于在相同模型和运行条件下复现结果，但模型版本、推理框架、硬件和服务端实现变化仍可能影响输出。
- 调参时从模型建议的默认设置出发，一次只改少数变量，并在代表性样例上比较质量、格式合规性、重复、延迟和成本；记录模型版本、提示词和完整参数。

## 1.6 关键区别

- 贪心每步选最高分；采样按概率抽取；束搜索在多条序列间搜索。它们解决的是不同的选择问题。
- 温度改变分布形状，Top-k、Top-p 和 Min-p 限制候选集合；没有一种设置能在所有模型和任务上保证更好的输出。
- 结构约束能控制输出形式，不能替代事实核验、Schema 校验或业务规则检查。
