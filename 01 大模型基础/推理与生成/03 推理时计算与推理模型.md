# 推理时计算与推理模型

复杂任务的效果不仅取决于模型参数，也取决于生成时允许模型使用多少计算、采用什么搜索或验证方式。推理时计算（test-time compute / inference-time compute）描述的是模型部署后，在一次请求中投入额外计算来改进结果的做法。

## 一、区分训练能力与运行时预算

常见生成过程可以概括为：

```text
消息与上下文 -> Prefill（处理输入） -> Decode（逐 Token 生成） -> 输出
```

模型先处理整个输入，再根据已生成的 Token 逐步产生后续内容。复杂推理任务可能会使用更多生成步骤，或在同一问题上产生多个候选，再通过搜索、验证或聚合选择结果。

| 机制 | 发生阶段 | 主要作用 |
| --- | --- | --- |
| 预训练 | 训练阶段 | 学习通用语言、知识和表示 |
| SFT、偏好优化、强化学习 | 后训练阶段 | 塑造指令遵循、任务策略、偏好和安全行为 |
| 推理时计算 | 模型调用阶段 | 给困难样本更多生成、搜索或验证预算 |

推理时计算不能补回模型完全不具备的能力，也不会自动保证答案正确。它适合在目标任务能被有效验证、额外预算确实能提升质量时使用。

## 二、推理模型的能力来源

“推理模型”通常指经过专门训练、在困难问题上会花更多步骤进行求解的模型形态。能力来源可能包括：

- 更适合推理的高质量训练数据
- SFT、偏好优化或强化学习等后训练
- 训练中对可验证任务的奖励或结果反馈
- 推理时更长的生成预算、搜索或检查
- 更适合任务的工具和外部验证器

这些组成因模型而异。有些产品提供“思考/快速”模式或推理预算参数；有些模型将推理过程作为内部 Token 处理，并不会向 API 用户完整返回。可见的思考文本长度并不是推理质量的可靠度量。

Chain-of-Thought、Self-Ask、ToT 等提示策略可以引导某些模型分步作答，但它们与专门训练的推理模型并非同一概念。策略介绍见 [04 CoT](04%20CoT.md)、[05 Self-Ask](05%20Self-Ask.md) 和 [06 ToT](06%20ToT.md)。

## 三、常见推理时计算策略

| 策略 | 做法 | 适用条件 | 主要代价 |
| --- | --- | --- | --- |
| 增加推理预算 | 允许模型生成更多推理或校验 Token | 复杂度差异较大、困难题需要更多步骤 | 延迟和输出 Token 增加 |
| 多候选采样与一致性聚合 | 生成多个候选，再投票或聚合答案 | 候选之间有一定独立性，且答案可比较 | 推理成本随候选数增长；错误可能高度相关 |
| 搜索与分支 | 展开多个候选步骤，用评分器或规则剪枝 | 有可比较的状态、清晰的约束或搜索空间 | 实现复杂，分支数可能快速增长 |
| 验证与修正 | 生成答案后调用程序、规则或模型检查，再修正 | 有可靠的单元测试、计算器、数据库或判定器 | 验证器可能有盲点，循环需要终止条件 |
| 工具辅助 | 将计算、检索或执行交给外部工具 | 工具能提供权威数据或确定性结果 | 工具权限、故障处理和结果可信度需治理 |

Best-of-N、Self-Consistency 和 ToT 都可以视为候选生成或搜索思路的不同形式。更多候选并不必然带来更好结果：当评分器无法区分好坏、候选错误相关或答案没有明确判据时，增加预算可能只增加成本。

## 四、Reasoning 与 Agent 的边界

模型可以生成工具调用意图，也可以在提示中规划多步问题；这描述的是模型的输出策略。由运行时负责执行工具、把结果写回对话、管理循环和权限的部分属于 Agent/Harness 层，见 [Agent与Harness](../../03%20Agent%E4%B8%8EHarness/README.md)。

类似地，本页讨论何时增加推理和搜索预算；KV Cache、连续批处理、投机解码、量化、Serving 和 GPU 调度属于 [推理与部署](../../04%20%E6%8E%A8%E7%90%86%E4%B8%8E%E9%83%A8%E7%BD%B2/README.md) 的运行时工程。

## 五、上线前如何验证收益

1. 按简单、普通、困难样本分桶，建立代表性评测集。
2. 用同一模型、提示和工具配置，对比普通预算与增强预算。
3. 同时记录任务成功率、事实错误、拒答、延迟、Token 和费用。
4. 对数学或代码等任务优先使用确定性验证器；对开放式任务采用人工抽查和成对偏好评估。
5. 设定预算上限、停止条件和回退策略；困难任务无收益时不要无条件增加预算。
6. 抽检长推理和拒答案例，避免把流畅解释误判为证据或正确性。

对于有验证器的任务，推理时计算可形成“生成候选 → 验证 → 选择/修正”的闭环。评测设计可参考 [09 Benchmark与常见指标](../模型原理与训练/09%20Benchmark%E4%B8%8E%E5%B8%B8%E8%A7%81%E6%8C%87%E6%A0%87.md)。
