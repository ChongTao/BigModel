# Self-Ask：子问题分解提示方法

Self-Ask 是一种提示模式：模型先判断问题是否需要追问，再生成并回答一系列子问题，最后汇总答案。它主要用于把多跳问题显式组织成较小的问答步骤。

**定位：Self-Ask 是问题分解提示方法，不是模型架构，也不是完整的 Agent 或工具执行算法。** 具体提示格式可以变化；加入搜索后，检索和工具执行由外部运行时负责。原始研究也讨论了 Self-Ask with Search。

## 1. 典型流程

1. 判断原问题能否直接回答；若不需要分解，就直接作答。
2. 找出结论依赖的中间事实或关系，生成数量尽可能少的追问。
3. 逐个回答追问。答案可以来自用户提供的上下文、模型已有知识或外部检索；来源不同，可信度也不同。
4. 检查中间答案是否足够、是否互相矛盾；缺少证据时继续查证或说明不确定。
5. 根据有依据的中间答案形成最终回答，并按要求保留引用或说明限制。

一种示意格式如下：

> Question: ...
>
> Are follow-up questions needed? Yes.
>
> Follow-up: ...
>
> Intermediate answer: ...
>
> Follow-up: ...
>
> Intermediate answer: ...
>
> Are follow-up questions needed? No.
>
> Final answer: ...

这是一种提示约定，不是固定的模型执行协议。应用若需调用检索或工具，仍要自行控制执行、结果回填和停止条件。

## 2. 示例：把多跳问题拆开

问题：电影《盗梦空间》的导演出生时，英国的君主是谁？

- 追问：电影《盗梦空间》的导演是谁？
  中间答案：克里斯托弗·诺兰。
- 追问：克里斯托弗·诺兰出生于何时？
  中间答案：1970 年 7 月 30 日。
- 追问：该日期英国的君主是谁？
  中间答案：伊丽莎白二世。
- 汇总：克里斯托弗·诺兰出生时，英国的君主是伊丽莎白二世。

这个例子展示了实体识别、日期确认和时间关系判断。实际使用时，中间事实应根据任务要求从可信资料中核对。

## 3. 适用场景与限制

| 场景 | 为什么可能有帮助 | 需要留意 |
| --- | --- | --- |
| 多跳事实问答 | 结论依赖数个可以分别回答的事实 | 每一步事实都可能过时或答错 |
| 条件组合与关系推断 | 把隐含前提分开处理，便于发现遗漏 | 子问题的拆分顺序可能不完整或错误 |
| 基于文档的复合问题 | 追问可以对应到不同证据片段 | 需要检索或文档上下文；Self-Ask 本身不会自动找到证据 |
| 简单、单跳问题 | 通常直接回答更省步骤 | 强行追问会增加 Token、延迟和错误传播机会 |

Self-Ask 能让问题分解过程更明确，但不保证比直接回答更准确或更稳定。若模型在内部独立回答所有子问题，错误仍会传递到最终结论；是否采用应通过代表性样例评估。

## 4. 与检索、工具和 Agent 的关系

Self-Ask 可以只用模型已有知识回答追问，也可以采用 Self-Ask with Search：将追问交给搜索或检索系统，再把证据带回模型继续推理。

使用检索或工具时：

- 为每个子问题检索相关证据，并在汇总时保留来源。
- 证据缺失或相互冲突时，允许模型说明无法确定，不要强行补全。
- 为追问数量、检索轮数和总时延设置上限。
- 工具调用参数、权限、实际执行和结果校验由应用或 Agent/Harness 管理；模型提出追问不代表工具已经运行。

因此，Self-Ask 可以成为检索工作流或 Agent 循环中的问题分解环节，但它本身不等同于 ReAct 这类“推理—行动—观察”模式。

## 5. 与相关方法的区别

| 方法 | 关注点 |
| --- | --- |
| CoT | 引导模型生成连续的中间推导；Self-Ask 将推导组织成明确的子问题与答案。 |
| Self-Consistency | 对多条候选推理路径的最终答案进行聚合；它可以与 Self-Ask 组合，但会增加采样与聚合步骤。 |
| ToT | 扩展并评估多个中间分支；Self-Ask 通常沿着子问题序列推进，不要求并行搜索分支。 |
| ReAct | 将推理与工具行动、观察结果组成循环；Self-Ask 只描述如何提出和回答子问题，工具执行需要外部运行时。 |
| 推理模型 | 指经过相应训练或后训练的模型能力形态；提示模型采用 Self-Ask 不等于训练出推理模型。 |

## 6. 使用与评估建议

1. 明确最终问题、需要的证据和答案格式；允许模型判断“无需追问”。
2. 限制追问数量和检索轮次，避免无关拆分。
3. 有事实依赖时，为每个中间答案保留证据或工具结果。
4. 在同一模型和样例上比较直接回答与 Self-Ask，评估正确率、遗漏、引用质量、Token、延迟和工具成本。
5. 若拆解没有稳定收益，或成本显著增加，就使用更直接的提示或其他验证方法。
