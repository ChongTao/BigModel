# Embedding

## Embedding 是什么

Embedding（嵌入或向量表示）是把对象映射为向量或向量序列的表示方法。大模型中的对象可以是 Token、文本、图像、音频或代码。

Embedding 通常用于表示、检索、匹配或分类，不负责直接生成答案。模型的训练目标决定了哪些对象会在表示空间中靠近。只有经过联合训练或对齐的表示，才适合跨模态比较；不同模型输出的向量通常不能直接互比。

例如，在与模型训练任务匹配时：

- 语义接近或任务相关的句子，可能在向量空间中更接近。
- 同一个 Token ID 的初始查表向量相同，经过上下文编码后得到的表示则可能不同。

Embedding 是很多能力的基础组件，例如：

- 语义搜索与向量检索
- 聚类与分类
- 推荐系统
- 文本相似度计算
- RAG 中的语义召回

但要注意：**Embedding 是一个宽泛概念，既可以指模型输入侧的 Token 查表向量，也可以指面向任务的句子、文档或其他对象表示。**这些表示的形状、训练目标和可比较范围可能不同。

## 从文本到表示

以常见的文本编码模型为例，文本表示通常经历以下步骤；具体模型可能使用不同的编码器和输出方式：

1. 分词：把文本切成 Token。
2. 编号：把 Token 映射到词表中的 ID。
3. 查表：把每个 Token ID 映射为初始向量。
4. 编码：经过序列模型处理，得到上下文化表示。
5. 生成任务表示：按模型设计使用特殊 Token、池化或任务头得到单向量；也可能保留多个 Token 向量或输出稀疏词项权重。

需要区分几个相关概念：

- `token embedding`：通常指查表得到的初始向量。
- `hidden states`：通常指序列模型处理后得到的上下文化表示。
- `text embedding`：通常指面向文本任务的模型表示；检索中常见的是句子或文档级向量，也可能是稀疏向量或多个 Token 向量。

三者相关，但不完全等价。

### Token Embedding

这是最狭义的 embedding，表示：

`token id -> 向量`

例如，词表中的某个 Token ID 查表后得到一个固定维度的向量。这一步是把离散符号映射到可计算空间。

### 上下文化表示

同一个 Token 进入序列模型（常见为 Transformer）后，会结合上下文更新表示。

因此：

- 初始 `token embedding` 是查表得到的参数向量。
- 经过模型层后的表示会受到上下文影响。

所以，同一个词在不同句子中的上下文化表示可能不同。

### Text Embedding

很多检索模型会把整句话或整段文本编码成一个单向量；也有模型保留多个 Token 向量，或输出稀疏词项权重。

单向量通常就是 RAG、向量数据库和语义检索里所说的 `embedding`。具体模型的输入格式、输出维度和向量兼容要求见 [RAG 检索](../../02%20%E6%A3%80%E7%B4%A2%E4%B8%8ERAG/RAG%E6%B5%81%E7%A8%8B/05%20RAG%E6%A3%80%E7%B4%A2.md)。

因此在工程语境里，口头所说的“做 embedding”很多时候是：

**把一段文本编码成可用于匹配的句向量、文档向量或其他检索表示。**

## 常见表示形式

### 稀疏向量

稀疏向量（Sparse Vector）是指大多数维度为 0、只有少量维度非零的表示。词项稀疏表示的维度通常对应词表或扩展词表中的词项。

例如，一个 1000 维向量里只有 10 个位置非零，就是典型的稀疏向量。

稀疏表示常见于：

- One-hot 表示和 TF-IDF。
- BM25 这类传统词项检索通常基于倒排索引和词项统计进行打分；**BM25 本身是排序函数，不是学习型 Embedding 模型。**
- SPLADE 等学习型稀疏模型会为词项生成权重，也可能扩展查询或文档中的词项。

由于大多数维度为 0，稀疏向量通常只存储非零值及其位置，而不完整保存所有维度。常见形式包括坐标列表、压缩稀疏行和索引到数值的映射。

例如，向量 `[0, 0, 1, 0, 0, 2]` 可以表示为索引 `[2, 5]` 对应数值 `[1, 2]`，或写成 `{ "2": 1, "5": 2 }`。实际索引从 0 还是 1 开始取决于具体实现。

### 稠密向量

稠密向量（Dense Vector）是指大多数维度都为非零值的向量表示。现代神经网络生成的文本表示常采用这种形式。

稠密向量通常有以下特点：

- 多个维度共同表达特征，单个维度未必有稳定、直观的含义。
- 输出维度和是否归一化由模型或接口规定；不同模型的向量通常不可直接混用。
- 常用于稠密向量检索、聚类、推荐和语义匹配。

稠密向量的质量依赖模型和训练任务。通用模型不一定适合领域检索；必要时应针对目标数据评测或微调。

### 多向量表示

有些检索模型会保留文本中多个 Token 的上下文化向量，而不是把整段文本压成一个向量。例如 ColBERT 使用 late interaction，在查询与文档的 Token 向量之间计算匹配。这种表示能保留细粒度匹配信息，但通常需要存储和比较更多向量。

因此，“Embedding”不一定意味着“每段文本对应一个固定长度的稠密向量”。单向量、稀疏向量和多向量表示可以服务于不同的检索目标，具体工程取舍见 [RAG 检索](../../02%20%E6%A3%80%E7%B4%A2%E4%B8%8ERAG/RAG%E6%B5%81%E7%A8%8B/05%20RAG%E6%A3%80%E7%B4%A2.md)。

## 相似度与训练目标

Embedding 的价值之一，是让系统可以比较两个表示之间的接近程度。常见度量包括：

- 点积（Dot Product）
- 余弦相似度（Cosine Similarity）
- 欧氏距离（Euclidean Distance）

余弦相似度主要比较方向；点积同时受方向和向量长度影响。如果两个向量都归一化为单位向量，点积在数学上等于余弦相似度（忽略浮点舍入误差）。欧氏距离也可使用，但应遵循模型和检索索引所采用的度量约定。

### 训练目标决定距离所表达的关系

Embedding 模型会按具体训练目标学习表示，例如利用相关与不相关样本优化检索排序或对比目标。向量距离反映的是模型学到的任务关系，不是对“普遍语义相同”的保证。

例如，如果模型的训练目标和数据覆盖了这类表达，下面两句话虽然字面不同，向量仍可能比较接近：

- “苹果手机性能很好”
- “这部 iPhone 跑分很强”

这类表示是语义检索能够工作的基础。相似度分数本身不是相关概率或答案正确率；对错误码、版本号、专有名词等精确词面要求高的任务，单靠稠密向量可能不足。不同检索方式的组合见 [RAG 检索](../../02%20%E6%A3%80%E7%B4%A2%E4%B8%8ERAG/RAG%E6%B5%81%E7%A8%8B/05%20RAG%E6%A3%80%E7%B4%A2.md)。

## Embedding 在大模型体系里的位置

从知识体系上看，Embedding 更偏表示学习能力，而不是生成能力本身。需要区分 Transformer 输入侧的 Token Embedding 参数与检索模型输出的句子、文档或多向量表示：它们有关联，但不是同一个对象。

它和以下内容密切相关：

- Transformer 中的 Token 表示
- 上下文化编码
- 表征学习
- 检索与匹配

它和以下内容需要区分：

- Prompt：组织对模型的指令和上下文。
- Generation：根据输入生成输出。
- Fine-tuning：通过训练使模型适配任务。

所以，Embedding 属于“大模型原理和表示层能力”的一部分；其具体检索用途则属于 RAG 等应用领域。

## Embedding 与 RAG 的关系

Embedding 本身是表示能力，而向量检索是它在 RAG 中的典型应用：

- Embedding 解决“对象如何表示为向量或向量序列”。
- 向量检索解决“如何用这些表示找出候选内容”。
- RAG 还要处理数据、召回、重排、上下文组织和生成。

因此，把 Embedding 的表示原理放在大模型基础中，把向量召回、索引、融合和重排放在 RAG 中，边界比较清晰。RAG 中的模型输入约定和检索流程见 [RAG 检索](../../02%20%E6%A3%80%E7%B4%A2%E4%B8%8ERAG/RAG%E6%B5%81%E7%A8%8B/05%20RAG%E6%A3%80%E7%B4%A2.md)。
