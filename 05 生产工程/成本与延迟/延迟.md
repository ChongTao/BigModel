# 大模型生产延迟治理

延迟直接影响交互体验、并发容量和调用成本。优化目标不是单纯降低平均值，而是在质量可接受的前提下，使端到端延迟、首 Token 延迟和尾延迟满足场景 SLA。

## 延迟构成

一次模型请求通常由以下部分构成：

`端到端延迟 = 排队 + 网络 + 网关处理 + Prompt 预填充 + 首 Token 生成 + 持续生成 + 工具调用 + 后处理`

| 指标 | 含义 | 适用场景 |
| --- | --- | --- |
| TTFT（首 Token 延迟） | 从提交请求到返回首个生成 Token 的时间 | 对话、流式交互 |
| TPOT（每输出 Token 时间） | 相邻输出 Token 的平均生成时间 | 长回答、代码生成 |
| E2E（端到端延迟） | 用户发起到结果可用的总时间 | 全部场景 |
| P50/P95/P99 | 中位数与尾部延迟 | SLA、容量治理 |
| 排队时间 | 请求进入服务到开始执行的等待 | 高峰期与限流诊断 |

输入上下文越长，预填充阶段通常越慢；输出越长，生成阶段越慢。工具链、检索、结构化校验和重试也会拉长端到端延迟，因此需要在网关统一记录各阶段耗时。

## 延迟目标与分层

先按业务建立时延预算，再把预算拆到各环节：

| 场景 | 示例目标 | 主要优化方向 |
| --- | --- | --- |
| 对话与 Copilot | 快速看到首 Token，持续流式输出 | 流式传输、缩短上下文、降低排队 |
| 工具调用与工作流 | 在合理总时限内可靠完成 | 并行化独立步骤、超时和降级 |
| 异步生成 | 结果在约定窗口内完成 | 队列吞吐、批处理和进度反馈 |
| 后台分析 | 吞吐优先 | 批量调度、资源利用率 |

不要用平均延迟代替体验指标：少量慢请求会显著破坏交互体验，应对 P95/P99 设置目标和告警。

## 优化手段

### 减少模型工作量

- 裁剪无关历史、检索结果和重复指令；为会话历史维护摘要。
- 设置与任务匹配的最大输出长度，要求简洁答案或结构化字段。
- 对稳定长前缀使用 Prompt Cache，减少重复预填充。
- 为简单任务路由到更快、更小的模型；复杂任务才升级。

### 缩短关键路径

- 对可流式返回的场景启用流式输出，优先优化 TTFT。
- 并行执行互不依赖的检索、工具调用和安全检查；仅串行保留真实依赖。
- 将非关键操作（评审、标签、归档）移到异步链路。
- 复用连接和客户端，减少重复握手；避免网关层的多次序列化与转发。

### 控制尾延迟

- 设置队列上限、并发上限和优先级，保护交互流量免受后台任务挤占。
- 为每个阶段设置超时；超时后返回可解释的降级结果或异步任务状态。
- 对幂等请求使用有限次数重试，并加入退避和抖动，避免重试风暴。
- 用隔离的资源池或配额区分高优先级、批处理和实验流量。

## 观测与排障

每个请求应携带贯穿网关、模型、检索和工具的追踪标识，记录模型版本、输入/输出 Token、缓存状态、队列时间、各阶段耗时、重试和最终状态。

当延迟异常时，按以下顺序定位：

1. 区分排队、网络、模型预填充、生成、工具调用或后处理的瓶颈。
2. 对比异常请求与正常请求的模型、上下文长度、输出长度、缓存命中和路由决策。
3. 检查限流、并发饱和、依赖服务错误率和重试量。
4. 在质量与成本不受损的前提下，灰度验证裁剪、路由或并发配置变更。

## 上线检查

- 为关键场景定义 TTFT、E2E 与 P95/P99 的 SLO。
- 在典型、长上下文和高并发负载下压测，而非只验证单次调用。
- 验证超时、取消请求、限流和降级后的用户反馈。
- 将 Prompt、模型和路由版本关联到延迟指标，保证变更可回滚。
