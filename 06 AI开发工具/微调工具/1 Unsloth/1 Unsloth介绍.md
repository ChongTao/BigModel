# Unsloth

[Unsloth](https://github.com/unslothai/unsloth) 是一个面向大语言模型（LLM）的开源训练与微调框架，主要用于降低模型训练的显存占用、提升训练速度，并简化开源大模型的微调流程。
传统大模型训练往往需要较高的 GPU 显存和计算资源，而 Unsloth 通过优化模型计算、梯度计算和内存管理等环节，降低微调所需的资源门槛，使开发者可以在单张 GPU 上完成部分原本需要更高配置的训练任务。

## 1. 核心功能

| 功能 | 说明 |
| --- | --- |
| 高效模型微调 | 支持使用 LoRA、QLoRA 等参数高效微调方法，对预训练模型进行领域适配或任务训练。相比更新全部模型参数，可以显著减少需要训练和保存的参数量。 |
| 降低显存占用 | 通过低比特量化、内存优化及高效计算实现更低的训练显存需求。对于显存约 8GB 的 NVIDIA GPU，可以尝试小参数模型和量化 LoRA 微调，但实际可行性取决于模型架构、序列长度、批次大小等因素。 |
| 支持多种训练任务 | 可用于监督微调（SFT）、对话模型训练、指令跟随、领域知识适配，以及通过 TRL 生态实现的部分偏好优化和强化学习训练流程。具体算法和模型的支持情况需以当前版本文档为准。 |
| 对接主流模型生态 | 与 Hugging Face 模型、分词器、数据集和训练工具协同工作，并可将训练后的模型或 LoRA 适配器导出到兼容的推理环境。 |

## 2. 软件架构

### 2.1 Unsloth Desktop

面向快速使用本地 AI 能力的用户，提供桌面应用入口，降低环境搭建和模型管理的复杂度。官方页面提供 Windows、macOS 和 Linux 等平台的下载方式。

主要适用场景：

- 下载和运行本地开源模型。
- 使用图形化界面管理模型。
- 开展模型训练和推理实验。
- 将本地模型接入 AI 编程工具。

### 2.2 Unsloth Studio

Unsloth Studio 是面向模型运行与训练的图形化 Web 界面，适合不希望从头编写大量训练代码的用户。官方资料介绍了可视化训练、数据集处理、训练过程监控以及模型导出等功能。

典型功能包括：

- 模型下载和管理。
- 训练数据导入与处理。
- 可视化配置训练任务。
- 查看训练损失、GPU 使用情况等指标。
- 运行模型、比较生成结果。
- 导出模型并对接推理环境。

### 2.3 Unsloth Core

Core 适合开发者和算法工程师的代码式训练方案。它允许通过 Python 控制模型加载、数据处理、训练参数、评估及模型保存等流程。

## 3. Unsloth 的典型工作流程

1. 选择基座模型：根据模型架构、参数规模、许可证、显存需求和目标任务选择预训练模型。
2. 准备训练数据：清洗数据，统一字段格式，划分训练集、验证集和测试集，检查标签质量。
3. 配置微调方法：选择 LoRA 或 QLoRA，设置学习率、训练轮数、序列长度、批次大小和适配器参数。
4. 执行训练：运行训练任务，观察 loss、显存占用、训练速度和异常日志。
5. 评估模型：在独立测试集上比较基座模型与微调模型，检查准确率、召回率、输出格式和错误案例。
6. 保存与导出：保存 LoRA 适配器，或在需要时合并权重并转换成目标推理格式。
7. 部署与监控：将模型接入推理服务，记录延迟、吞吐量、错误率、资源使用情况和业务效果。

## 4. 实战参数配置与训练指标

实战文档包含两组单卡示例：Gemma 3 270M 使用 16 条问答样例验证 LoRA 训练流程；Qwen3 0.6B 使用 ChnSentiCorp 的 500 条训练样例和 100 条测试样例演示情感分类。以下参数用于说明各配置项的作用，具体取值需结合模型、数据和硬件调整。

### 4.1 模型与 LoRA 配置

| 配置项 | Gemma 3 270M 示例 | Qwen3 0.6B 示例 | 说明 |
| --- | --- | --- | --- |
| 最大序列长度 | 训练时 512；加载与分词检查时 1024 | 256 | 限制单条样本的 token 长度。调大通常会增加显存、内存和计算开销；过小则可能截断输入或答案。 |
| 基座模型精度与量化 | float32，未启用 4-bit | 支持时使用 bfloat16，未启用 4-bit | 两组示例都是普通 LoRA 配置，不是 QLoRA。模型精度影响权重内存与运算兼容性；CPU 是否支持 bfloat16 取决于处理器和 PyTorch 构建。 |
| `r` 与 `lora_alpha` | 8 与 16 | 16 与 32 | `r` 是低秩适配器的维度，越大通常意味着更多可训练参数和更高适配容量；`lora_alpha` 控制适配器更新的缩放，不等同于学习率。 |
| `target_modules` | `q_proj`、`k_proj`、`v_proj`、`o_proj`、`gate_proj`、`up_proj`、`down_proj` | 同左 | 指定在哪些线性层插入 LoRA，覆盖注意力投影和 MLP 投影层。模块名称随模型架构变化，配置前应确认目标模型确实包含这些层。 |
| `lora_dropout` 与 `bias` | 0.05 与 `none` | 0.05 与 `none` | `lora_dropout` 在 LoRA 分支上施加 dropout，可用于降低过拟合风险；`bias=none` 表示不训练偏置参数。 |
| 梯度检查点与随机种子 | 关闭；3407 | 关闭；3407 | 梯度检查点用额外计算换取较低的激活内存占用，示例为简化流程而关闭。随机种子帮助复现实验，但不同硬件和软件版本仍可能产生差异。 |

### 4.2 训练与评估配置

| 配置项 | Gemma 3 270M 示例 | Qwen3 0.6B 示例 | 说明 |
| --- | --- | --- | --- |
| 批次大小 | 每设备 1，梯度累积 4 | 每设备训练批次 1、评估批次 1，梯度累积 4 | 单设备下有效训练批次大小为 1 × 4 = 4；多设备训练时还需乘以设备数。梯度累积可以在较小显存下模拟更大的批次。 |
| 训练长度 | `max_steps=10`；数据集 16 条 | 训练集 500 条，训练 1 个 epoch，约 125 次更新 | Gemma 示例约遍历数据 2.5 轮，仅用于验证流程；Qwen 示例也只抽取了部分数据，不能代表完整数据集的效果。 |
| 学习率 | `2e-4` | `2e-4` | 控制优化器每次更新可训练参数的步幅。过大可能使训练不稳定，过小则可能收敛较慢。它是调度器使用的目标学习率，日志中的实际值会随预热和学习率调度变化。 |
| 预热与调度 | 预热 2 步，未显式指定调度器 | 余弦调度，预热比例 0.05 | 预热在训练初期逐步提高学习率；Qwen 配置按总训练步数的约 5% 预热，随后按余弦曲线衰减。 |
| 优化器与精度选项 | `adamw_torch`；float32，`fp16`、`bf16` 均关闭 | `adamw_torch`；基座权重按 `bfloat16` 加载，Trainer 的 `fp16`、`bf16` 选项关闭 | 优化器负责更新 LoRA 参数。模型加载精度与 Trainer 的混合精度开关是不同配置；Qwen 示例需确认 CPU/PyTorch 支持 bfloat16，不支持时应改用兼容精度并重新评估内存。 |
| 日志、评估与保存 | 每步记录训练日志；不做定期评估或 checkpoint，训练结束后保存适配器 | 每 10 步记录日志、每 25 步评估、每 50 步保存并最多保留 1 个 checkpoint | `report_to=[]` 关闭外部实验跟踪。`save_only_model=True` 只保存模型权重，不包含完整优化器、调度器和随机状态，不能视为完整的训练状态备份。 |

### 4.3 训练日志与结果指标

| 输出项 | 含义与阅读方式 |
| --- | --- |
| `loss` / `train_loss` | 训练文本上的交叉熵损失，反映下一个 token 的预测误差。下降说明训练集拟合程度发生变化，但不能单独证明模型效果提升或具备泛化能力。 |
| `grad_norm` | 梯度的全局 L2 范数，可观察梯度规模和突变；没有适用于所有模型的固定阈值，需结合 loss 和训练过程判断。 |
| `learning_rate` | 当前优化步使用的实际学习率。它可能从较小值预热到配置值，再按调度策略衰减，因此不会始终等于 `2e-4`。 |
| `entropy` | 模型预测分布的熵，可辅助观察预测分布的不确定程度；不宜单独作为模型质量指标。 |
| `mean_token_accuracy` | 训练 token 的 top-1 预测准确率，衡量 token 级预测，不等于问答质量或分类任务准确率。 |
| `num_tokens` 与 `epoch` | 前者是训练日志记录的 token 计数，具体统计口径可能随 Transformers/TRL 版本变化；后者表示数据集遍历进度，例如 2.5 表示约完成 2.5 轮。 |

分类示例还会输出 `eval_loss`、困惑度、`baseline_accuracy`、`finetuned_accuracy` 和 `invalid` 数量。困惑度由 token 级损失计算，不等于分类准确率；分类准确率来自生成标签的解析，`invalid` 统计没有生成可识别标签的样本。基线与微调后结果使用同一测试集，便于对照，但 100 条测试样例仍不足以代表更广泛的数据分布。`trainable_params_M` 和训练参数占比描述可训练适配器规模；`lora_size_MB` 是保存文件大小；`peak_memory_mb` 是进程峰值主机内存，不是 GPU 显存。
