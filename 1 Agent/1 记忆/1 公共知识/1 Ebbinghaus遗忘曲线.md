# Ebbinghaus 遗忘曲线

## 一、什么是 Ebbinghaus 遗忘曲线

Ebbinghaus 遗忘曲线（Ebbinghaus Forgetting Curve）描述了一个常见现象：当学习后没有复习或再次使用信息时，对信息的保留会在早期快速下降，随后下降速度逐渐变慢。

它来自德国心理学家 Hermann Ebbinghaus 在 19 世纪末进行的记忆实验。为尽量排除既有知识的影响，他用无意义音节作为材料，记录自己在不同间隔后重新学习这些材料所需的时间。重新学习所节省的时间，被称为**节省量（savings）**，可作为记忆仍被保留的近似信号。

曲线传达的核心不是“人会在固定时间点忘掉固定比例”，而是：

- 刚形成、未巩固的记忆最容易丢失；
- 经过一段时间后仍被保留的内容，相对更稳定；
- 复习、回忆和再次使用能够减缓遗忘；
- 记忆强度会随内容、学习方式、任务和个体而变化。

## 二、曲线的典型形状

可以用下图理解保留率随时间下降的趋势：

```text
保留率
100% ┤●
     │  ●
     │    ●
     │       ●
     │          ●──────
  0% ┼────────────────── 时间
       学习后早期      较长时间后
```

学习后的最初一段时间通常下降最快；随着时间推移，曲线趋于平缓。这里的“平缓”不代表记忆不会继续变化，而是说明同样增加一段时间，带来的额外遗忘往往更少。

网上常见“20 分钟后忘记多少、一天后忘记多少”的固定百分比表格，只能作为直观示例，不能视为普适定律。原始实验材料、实验条件和现代真实学习场景差异很大；把这些数字直接用于产品策略或 Agent 系统没有充分依据。

## 三、常见数学表达

遗忘曲线常用衰减函数近似，而不是唯一、精确的物理定律。

### 3.1 指数衰减模型

一个常见近似是：

```text
R(t) = exp(-t / S)
```

其中：

- `R(t)`：经过时间 `t` 后的保留强度或保留概率，取值通常在 0 到 1；
- `t`：距上次学习、确认或使用的时间；
- `S`：稳定性（stability）或时间尺度；`S` 越大，衰减越慢；
- `exp`：自然指数函数。

当 `t = S` 时，`R(t)` 约为 0.37。它不是“记得 37% 内容”的精确含义，而是模型中的相对强度已经降至初始值的约 37%。

### 3.2 幂律或可调衰减模型

在不同数据上，也常使用更灵活的形式，例如：

```text
R(t) = (1 + t / S)^(-d)
```

其中 `d` 控制曲线形状。与简单指数模型相比，这类模型可以更好地拟合某些“前期陡降、后期长尾”的数据。

实际系统不应纠结哪一个公式“唯一正确”，而应将公式视为排序与治理的近似工具，并用自身数据校准参数。

## 四、什么决定遗忘速度

遗忘速度不是只由时间决定。以下因素都会影响曲线：

| 因素 | 对遗忘的常见影响 |
| --- | --- |
| 初始编码质量 | 理解、关联和主动回忆通常比机械重复更稳定。 |
| 内容类型 | 稳定事实、短期状态、情节细节的有效期不同。 |
| 重复与间隔复习 | 有效复习和再次使用通常会提高稳定性。 |
| 重要性与情绪 | 高价值、高风险或强情绪事件更容易被保留。 |
| 干扰与冲突 | 相似信息、后续新信息可能造成混淆或覆盖。 |
| 检索练习 | 主动回忆往往比只重新阅读更能巩固记忆。 |
| 上下文匹配 | 在相似任务或线索下更容易成功回忆。 |

因此，一条“用户偏好中文回答”和一条“用户今天临时在上海出差”，不应使用相同的衰减参数：前者通常更稳定，后者则应具有更短的有效期。

## 五、遗忘曲线与间隔重复

**间隔重复（spaced repetition）**是遗忘曲线最常见的应用思路：在记忆即将难以成功提取之前进行复习或使用，使其重新变强，并拉长下一次复习间隔。

简化过程如下：

```text
学习/写入 → 保留强度下降 → 临近阈值时复习或成功检索
                           ↓
                    强度恢复、稳定性提高
                           ↓
                   下一次复习间隔变长
```

这里的关键不是死记固定的“第 1 天、第 3 天、第 7 天”，而是根据历史表现、难度和重要性动态安排。若复习时仍能正确回忆，通常应提高稳定性；若已经遗忘，则可能需要更短的下一次间隔或重新编码。

## 六、在 Agent Memory 中如何使用

遗忘曲线可以为 Agent 记忆系统提供“随时间降权”的启发，但 Agent 记忆不是人类学习，不能直接照搬人类实验结论。更合适的用途包括以下几类。

### 6.1 作为检索排序特征

在语义相关性之外，为候选记忆计算时间新鲜度或保留强度：

```text
score = w1 × relevance + w2 × retention + w3 × importance + w4 × confidence
```

其中 `retention` 可由衰减函数计算。这样，近期且相关的任务状态会更容易被召回；但高重要性的稳定事实不会仅因时间久远而完全消失。

### 6.2 作为归档、压缩与删除信号

对于低价值、长期未使用且已经过期的情节记忆，可依次采取：

1. 降低检索权重；
2. 从热存储迁移到冷存储；
3. 与相近事件合并为摘要；
4. 在满足保留与审计要求后删除。

这比直接按时间一刀切删除更稳妥。涉及合规、用户删除权或业务审计的记录，必须由明确的数据策略决定，不能仅由衰减分数自动处理。

### 6.3 作为写入与更新策略的辅助条件

写入记忆时可以初始化不同的稳定性：

- 已确认、反复出现的用户偏好：较高稳定性；
- 工具调用产生的临时状态：较低稳定性，附带明确 TTL；
- 未确认推断：低置信度，不直接作为长期事实；
- 高风险约束或安全规则：不按普通遗忘曲线衰减，应由版本和治理策略管理。

当一条记忆被成功检索并在任务中验证有用时，可提高它的稳定性或重要性；当新事实与它冲突时，应走版本、更新或失效流程，而不是仅等待它自然衰减。

### 6.4 用 Jaccard 建立版本与覆盖关系

记忆演化时，系统需要判断新旧记录是重复、局部重叠，还是新版对旧版的覆盖。对于可表示为标签、实体、属性或关键词集合的记忆，可使用 **Jaccard 相似度** 做初步判断：

```text
J(A, B) = |A ∩ B| / |A ∪ B|
```

`A ∩ B` 是两个集合的共同元素，`A ∪ B` 是全部不重复元素。结果越接近 1，表示重叠越高；为 0 则表示没有共同元素。

例如：

```text
旧记忆 A：{用户, 偏好中文, 使用 Go}
新记忆 B：{用户, 偏好中文, 使用 Go, 使用 Kubernetes}
```

此时 `J(A, B) = 3 / 4 = 0.75`，且 `A ⊂ B`：新记忆包含旧记忆的全部信息并补充了新信息。系统可建立如下关系：

```text
B ──covers──> A
B ──newer / richer version of──> A
```

可按以下原则处理：

- **完全相同或近乎相同**：去重，保留来源、时间与版本历史。
- **新记录包含旧记录**：将新记录标为更完整版本，旧记录保留为历史版本或被合并。
- **高度重叠但互不包含**：合并互补字段，或保留为关联的并列版本。
- **低重叠**：视为独立记忆，不应仅因属于同一用户而强行合并。

Jaccard 只衡量集合重叠，无法识别“表述不同但语义相同”的文本，也不能判断事实真伪。因此实际决策还应结合时间戳、来源、置信度、实体一致性和语义相似度。新记录被判为“更完整”，也不代表它一定更可信。

### 6.5 一个简化的数据模型

可为每条记忆保存类似字段：

```text
memory_id
content
type                 # preference / fact / episode / task_state
created_at
last_confirmed_at
last_accessed_at
importance
confidence
stability
expires_at           # 可选，适合临时信息
source
```

在读取时，系统根据 `last_confirmed_at` 计算衰减；在成功使用或人工确认后更新 `last_confirmed_at`、`stability` 或 `confidence`。`last_accessed_at` 可以反映使用频率，但“被访问”不等同于“事实仍然正确”，因此不能替代确认时间。

## 七、落地时的常见误区

### 7.1 只按时间删除

时间久不等于无价值。用户长期偏好、关键约束、审计记录和业务事实都可能需要长期保留。应先区分记忆类型、用途、权限和保留策略。

### 7.2 把衰减分数当成真实性分数

衰减反映的是“是否应优先召回或复核”，不能证明内容为真。真实性需要来源、置信度、交叉验证和冲突处理支持。

### 7.3 用一次命中无限强化错误记忆

被检索到不代表被验证正确。只有在任务结果、用户确认或可信来源支持时，才应显著提高稳定性。

### 7.4 对所有记忆使用同一条曲线

不同类型的记忆需要不同策略：任务状态倾向于短 TTL，用户偏好需要缓慢衰减，动态事实需要更强调最新确认时间，安全规则则应该版本化管理。

### 7.5 让自动遗忘绕过治理要求

隐私删除、合规保留、审计追踪、租户隔离和访问控制优先于自动衰减策略。遗忘机制应可解释、可配置、可回溯。

## 八、实践建议

1. 先按 `fact`、`preference`、`episode`、`task_state` 等类型定义保留规则。
2. 从简单的时间衰减排序开始，不要一开始就自动物理删除数据。
3. 将时间、新鲜度、重要性、置信度、来源和语义相关性一起用于检索。
4. 把“成功验证”“用户确认”“冲突出现”作为调整稳定性的事件。
5. 用离线回放评估：衰减是否减少了检索噪声，是否遗漏了仍有价值的信息。
6. 为高价值或高风险记忆提供人工复核、版本历史和明确的删除流程。

## 九、与记忆生命周期的关系

遗忘曲线主要服务于记忆的“演化”阶段，而不是替代完整的记忆管理。一个成熟系统仍需要：

- 在写入时判断信息是否值得记住；
- 在更新时处理冲突、确认和版本；
- 在检索时综合相关性、权限、时间和可靠性；
- 在删除时遵循隐私、合规和业务保留要求。

相关的系统设计见：[记忆架构与生命周期](../2%20记忆架构与生命周期.md)。

## 十、总结

Ebbinghaus 遗忘曲线揭示了记忆会随时间衰减、且早期遗忘更快的经验规律。对 Agent Memory 而言，它最适合被用作新鲜度排序、归档压缩和复核触发的启发式模型。

真正可用的遗忘机制，不是把所有信息套进同一公式后自动删除，而是在记忆类型、重要性、置信度、来源、访问权限和业务规则之上，谨慎地让低价值信息逐步降权，让已确认且仍有用的信息保持可用。
