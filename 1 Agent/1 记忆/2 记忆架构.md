# Agent 记忆架构

Agent Memory 不是某一种数据库，也不是聊天记录的无差别归档。它由写入、存储、检索和上下文组装等模块构成；各阶段的执行过程见[记忆生命周期](./3%20记忆生命周期.md)。

## 一、最小系统架构

```text
用户/环境/工具事件
        │
        ▼
  观察与候选记忆 ──► 写入策略 ──► 记忆存储
        ▲                              │
        │                              ▼
Agent 决策 ◄── 上下文组装 ◄── 检索、过滤与排序
```

这五个模块的职责应分开：

- **观察与候选记忆**：从对话、工具结果和任务事件中识别可能有价值的信息。
- **写入策略**：决定是否写入、写成什么类型、是否覆盖或合并旧记忆。
- **记忆存储**：按访问模式保存事实、事件、任务状态和关系。
- **检索、过滤与排序**：根据当前用户、任务、时间和查询找回候选内容，再控制其数量和质量。
- **上下文组装**：将少量、可验证、与当前步骤直接相关的信息放入模型上下文。

模型不应直接获得整个记忆库；“检索正确”与“上下文可用”是两个独立问题。

## 二、同步读路径与异步写路径

面向用户请求的路径应优先保证低延迟和可控上下文；耗时的抽取、归并和索引工作则适合在后台完成。

```text
同步读路径：请求 → 身份/权限过滤 → 检索与排序 → 上下文预算 → Agent 决策
异步写路径：事件 → 候选记忆 → 抽取与治理 → 存储/建索引 → 审计与观测
```

- **同步读路径**：只读取已完成治理的记忆；在检索失败、超时或结果质量不足时，回退为不使用长期记忆的当前任务推理。
- **异步写路径**：通过队列或后台任务处理摘要、去重、冲突检测和向量/图索引，避免增加用户请求延迟。
- **任务状态例外**：对恢复任务必需的检查点，可同步写入状态存储；写入应具备幂等性，避免重试产生重复状态。

## 三、记忆对象与治理控制面

不同后端可以有不同表结构，但一条可管理的记忆至少应包含以下元数据：

| 字段 | 作用 |
| --- | --- |
| `memory_id`、类型与内容 | 唯一定位记忆，并区分事实、偏好、事件、任务状态等用途 |
| 用户 / 租户 / 会话命名空间 | 作为读写隔离的首要约束 |
| 来源、证据与置信度 | 区分用户明确陈述、工具结果和模型推断，支持追溯与冲突处理 |
| 创建时间、更新时间、有效期与版本 | 支持时效判断、版本回溯和遗忘策略 |
| 权限标签与删除状态 | 支持最小权限检索、删除请求和审计 |
| 索引引用 | 关联向量、关键词或图索引，避免把索引当作唯一事实来源 |

权限和隐私策略应作为横切控制面，而不是存储后的补救措施：写入前执行敏感信息与权限检查；检索前按主体、租户和 ACL 过滤；删除时同步处理正文、索引和派生摘要。

## 四、上下文组装与降级

检索结果进入模型前，还需要经过上下文组装层。它负责：

- 为记忆设置 token 预算，并优先保留与当前步骤直接相关、来源可靠且未过期的信息。
- 对相似结果去重；发生冲突时优先使用最新且高置信度的版本，或向用户/Agent 标记待确认。
- 把事实、偏好、事件和任务状态按不同模板组织，避免把原始历史片段无差别拼接进 prompt。
- 记录每次召回和最终使用的记忆，便于解释、调试和离线评测。

当权限校验失败、检索超时或没有高质量结果时，系统应返回空记忆上下文而不是放宽过滤条件；Agent 需要能在该降级路径下继续完成当前任务。

## 五、存储建模与适用边界

| 信息形态 | 常见存储 | 适用场景 |
| --- | --- | --- |
| 会话状态、计划、检查点 | KV / 状态存储 | 任务恢复、工作记忆 |
| 用户偏好、稳定事实 | 结构化记录 | 个性化、配置与权限 |
| 历史事件与摘要 | 文档库 + 向量索引 | 语义回忆、跨会话经验 |
| 实体、关系与时间变化 | 图数据库 | 关系推理、动态世界状态 |
| 原始记录与审计日志 | 对象存储 / 日志库 | 追溯、重新抽取与评测 |

向量库只是语义召回的一种后端；它不能天然处理权限、冲突、时间有效性和结构化更新。实际系统常采用混合存储。

## 六、可靠性与可观测性

为避免“写入成功但不可检索”或“已删除仍被召回”，架构应记录并监控：

- 写入、索引、删除和重建任务的状态、重试次数与失败原因。
- 记忆 ID、请求 ID 与来源之间的关联，形成可审计的读写链路。
- 召回数量、上下文 token、端到端延迟和存储成本，以及权限拦截、冲突和过期记忆的比例。

这些指标既是线上故障排查的依据，也能与[基准与评测](./20%20实践与评测/2%20基准与评测.md)中的写入质量、检索质量和安全指标形成闭环。
