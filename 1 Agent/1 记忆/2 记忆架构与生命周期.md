# Agent 记忆架构与生命周期

Agent Memory 不是某一种数据库，也不是聊天记录的无差别归档。它是一条将交互信息转化为可复用状态、并在合适时机带回推理过程的闭环。

## 一、最小系统架构

```text
用户/环境/工具事件
        │
        ▼
  观察与候选记忆 ──► 写入策略 ──► 记忆存储
        ▲                              │
        │                              ▼
Agent 决策 ◄── 上下文组装 ◄── 检索、过滤与排序
```

这五个模块的职责应分开：

- **观察与候选记忆**：从对话、工具结果和任务事件中识别可能有价值的信息。
- **写入策略**：决定是否写入、写成什么类型、是否覆盖或合并旧记忆。
- **记忆存储**：按访问模式保存事实、事件、任务状态和关系。
- **检索、过滤与排序**：根据当前用户、任务、时间和查询找回候选内容，再控制其数量和质量。
- **上下文组装**：将少量、可验证、与当前步骤直接相关的信息放入模型上下文。

模型不应直接获得整个记忆库；“检索正确”与“上下文可用”是两个独立问题。

## 二、写入：从事件到记忆

写入前先区分原始事件与长期记忆。原始事件可追溯，但通常噪声较大；长期记忆应是可复用、稳定且有来源的信息。

常见流程：

1. **捕获**：记录对话片段、工具结果或任务状态变化。
2. **抽取**：提取事实、偏好、事件、关系或可复用策略。
3. **判定**：根据稳定性、重要性、置信度和隐私策略决定是否持久化。
4. **归并**：查找同一主体、同一字段或相似语义的旧记忆。
5. **演化**：新增、更新、合并、标记失效或删除，并保留来源与时间信息。

例如，“用户今天在上海出差”适合作为有时效的事件；“用户偏好中文回答”适合作为可更新的用户偏好。将两者同等永久保存会造成记忆污染。

## 三、检索：相关性不等于可用性

检索一般先做硬约束过滤，再进行软排序：

```text
user / tenant / 权限过滤
  → 任务、实体、时间等元数据过滤
  → 向量、关键词或图检索
  → 重排、去重、冲突检测
  → 预算截断与上下文组装
```

排序可综合语义相关性、时间新鲜度、重要性、来源可信度和访问成本。偏好或事实应优先使用最新且置信度更高的版本；情节记忆则应保留事件时间和发生顺序。

## 四、演化与遗忘

记忆系统最难的部分不是写入，而是避免“越记越错”。至少应具备以下策略：

- **版本与来源**：保存记忆来自何处、何时产生、由谁确认。
- **冲突处理**：新信息与旧事实冲突时，更新当前值、保留历史版本，或标记待确认。
- **合并去重**：将语义重复的记忆压缩为更稳定的摘要或结构化字段。
- **过期与衰减**：为易变化信息设置有效期，或按访问频率、时间和价值降低权重。
- **删除权与隔离**：按用户、租户和权限边界删除或屏蔽记忆，避免跨主体泄漏。

“遗忘”不是故障，而是维持检索质量、成本和隐私边界的必要能力。

## 五、存储建模与适用边界

| 信息形态 | 常见存储 | 适用场景 |
| --- | --- | --- |
| 会话状态、计划、检查点 | KV / 状态存储 | 任务恢复、工作记忆 |
| 用户偏好、稳定事实 | 结构化记录 | 个性化、配置与权限 |
| 历史事件与摘要 | 文档库 + 向量索引 | 语义回忆、跨会话经验 |
| 实体、关系与时间变化 | 图数据库 | 关系推理、动态世界状态 |
| 原始记录与审计日志 | 对象存储 / 日志库 | 追溯、重新抽取与评测 |

向量库只是语义召回的一种后端；它不能天然处理权限、冲突、时间有效性和结构化更新。实际系统常采用混合存储。
