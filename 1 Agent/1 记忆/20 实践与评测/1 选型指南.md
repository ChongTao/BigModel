# Agent 记忆选型指南

选型先回答“需要记住什么、何时失效、如何证明正确”，再选择框架或数据库。不要仅因方案提供向量检索就将其视为完整的记忆系统。

## 一、按问题选择能力

| 主要需求 | 首选能力 | 可优先考察的方案 |
| --- | --- | --- |
| 长期用户画像与偏好 | 结构化 profile、事件沉淀、更新治理 | Memobase、Mem0 |
| 长任务与上下文窗口调度 | memory hierarchy、检查点、上下文换入换出 | MemGPT / Letta |
| 实体关系和时间变化 | 时序图、图检索、关系更新 | Graphiti、Neo4j Agent Memory |
| 在 LangGraph 中轻量接入 | memory tools、后台整理、可插拔 store | LangMem |
| 外部文档问答 | 文档解析、RAG、权限检索 | 向量库 / RAG，而非单独的 Agent Memory |

具体方案的架构差异见[记忆方案对比](../3%20记忆方案对比.md)。

## 二、落地前检查清单

- 明确记忆主体：用户、会话、任务、Agent 还是租户。
- 为每类记忆定义 schema、来源、时间、置信度和有效期。
- 明确写入阈值和冲突规则，避免将猜测写成事实。
- 明确检索的权限过滤与上下文 token 预算。
- 设计删除、导出和审计流程，尤其是用户画像类记忆。
- 用真实任务集验证收益，而不是只验证“能检索到内容”。

## 三、推荐的最小起步方案

先从“会话状态 + 少量结构化长期事实 + 可追溯事件日志”开始。确认确有语义回忆或关系推理需求后，再增加向量索引或图数据库。这样更容易定位错误来源，也避免过早引入难以治理的自动记忆。
