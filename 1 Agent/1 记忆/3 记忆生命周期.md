# Agent 记忆生命周期

Agent Memory 的生命周期描述信息如何从一次交互变成可复用状态，并在后续任务中安全、准确地参与决策。它不是“写入即结束”的直线，而是捕获、判定、巩固、检索、使用、演化、衰减与删除构成的闭环。模块划分与职责边界见[记忆架构](./2%20记忆架构.md)，记忆类型与相关概念区分见[记忆概述](./1%20记忆概述.md)。

## 一、生命周期总览

### 1.1 三条路径

```text
写入侧：捕获 → 抽取 → 判定 → 写入 → 巩固与索引
读取侧：过滤 → 召回 → 重排 → 预算截断 → 组装与使用
维护侧：反馈强化 → 更新 / 合并 / 失效 → 衰减 → 归档 → 删除
```

三条路径互相闭环：读取侧产生“哪些记忆真的被用到”的反馈，维护侧据此调整强度、修正冲突、淘汰噪声，写入侧再决定下一次记什么、怎么记。缺少维护侧的系统会退化成“只增不减的日志”。

### 1.2 阶段职责与典型失效

| 阶段 | 输入 → 输出 | 关键决策 | 典型失效 |
| --- | --- | --- | --- |
| 捕获 | 对话、工具结果、任务事件 → 原始事件 | 是否保留原文、保留多久 | 全量落库，噪声与敏感内容入库 |
| 抽取 | 原始事件 → 候选记忆 | 抽成什么类型、什么粒度 | 把推测当事实，粒度过粗无法更新 |
| 判定 | 候选记忆 → 写入决策 | 是否持久化、写入哪个命名空间 | 短期状态被固化为长期事实 |
| 写入 | 写入决策 → 带元数据的记忆记录 | 新增 / 更新 / 合并 / 失效 | 重复写入，覆盖丢失历史 |
| 巩固与索引 | 记忆记录 → 索引、摘要、归一实体 | 何时建索引、如何消歧 | 写入成功但不可检索 |
| 检索 | 查询与上下文 → 候选集合 | 过滤条件与排序信号 | 越权召回、过期召回 |
| 组装与使用 | 候选集合 → 进入 prompt 的片段 | token 预算与组织模板 | 无关记忆挤占上下文 |
| 反馈强化 | 使用结果 → 强度与置信度调整 | 命中是否加权、纠错如何降权 | 只写不评，错误被反复强化 |
| 演化 | 新旧记忆冲突 → 当前值 + 历史版本 | 覆盖、并存还是待确认 | 新旧事实同时主导回答 |
| 衰减与归档 | 长期未用记忆 → 降权、冷存、摘要 | 衰减参数与阈值 | 一刀切删除，或热存储持续膨胀 |
| 删除 | 合规或纠错请求 → 正文、索引、派生摘要清理 | 删除范围与留痕方式 | 已删除仍被召回 |

### 1.3 记忆状态机

一条记忆在生命周期中会经历明确的状态迁移，检索层只应看到允许参与决策的状态：

```text
候选 candidate ──判定通过──► 生效 active ──巩固──► 已巩固 consolidated
     │                       ▲    │                     │
  判定拒绝                   │  冲突 / 纠错       过期 / 被取代 / 长期未命中
     ▼                       │    ▼                     ▼
  丢弃 discard               └─ 待确认 disputed    已失效 invalidated
                                                        │
                                                   冷存 / 摘要合并
                                                        ▼
                                                 已归档 archived
                                                        │
                                                   合规 / 清理
                                                        ▼
                                                 已删除 deleted
```

| 状态 | 含义 | 可否参与检索 | 常见进入条件 |
| --- | --- | --- | --- |
| 候选 | 已抽取但未通过治理 | 否 | 抽取完成，等待判定 |
| 生效 | 已写入并可被召回 | 是 | 判定通过并完成写入 |
| 已巩固 | 已建索引、已归一或已合并 | 是 | 后台巩固任务完成 |
| 待确认 | 存在冲突或低置信度 | 受限，需标注 | 冲突检测、用户纠错 |
| 已失效 | 事实过期或被推翻 | 否，仅用于追溯 | 有效期到期、新版本取代 |
| 已归档 | 迁出热存储的冷数据 | 需显式查询 | 长期未命中、成本策略 |
| 已删除 | 正文与索引均已清理 | 否 | 删除请求、合规清理 |

状态迁移必须留痕：谁在什么时候、依据什么证据把记忆从 `active` 变成 `invalidated`，是排查“为什么 Agent 突然不记得了”的唯一线索。

## 二、捕获与抽取

### 2.1 捕获：区分原始事件与候选记忆

原始事件可追溯、可重放，但噪声大且常含敏感内容；候选记忆应是可复用、稳定且有来源的信息。两者应分开存放：原文进入日志或对象存储用于审计与重新抽取，进入记忆库的只应是加工后的结果。

常见捕获时机：

- 一个对话回合结束，或一次任务阶段完成；
- 工具调用返回结构化结果（订单状态、检索结果、执行日志）；
- 任务状态发生变化（计划更新、子任务完成、检查点写入）；
- 用户或 Agent 显式要求“记住这件事”；
- 运行时 hook 自动采集，无需业务代码手动调用。

### 2.2 抽取：确定类型与粒度

| 抽取目标 | 常见形态 | 示例 | 时效特征 |
| --- | --- | --- | --- |
| 稳定事实与偏好 | 结构化槽位 | 用户偏好中文回答 | 长期，可更新 |
| 事件与情节 | 带时间戳的摘要 | 9 月在上海出差 | 短期，需有效期 |
| 实体与关系 | 图三元组 | A 负责 B 项目 | 中期，会失效 |
| 任务状态 | KV / 检查点 | 第 3 步已完成并验证 | 任务内有效 |
| 程序性经验 | 可复用策略或教训 | 该接口需先鉴权再分页 | 长期，需重复验证 |

抽取质量决定后续所有阶段的上限，应遵守几条约束：

- **原子性**：一条记忆只表达一个可独立验证的断言，便于更新、去重和冲突检测。
- **可追溯**：保留证据指针（消息 ID、工具调用 ID、文档片段），而不是只留结论。
- **来源分级**：区分用户明确陈述、工具返回结果和模型推断，赋予不同默认置信度。
- **不记推理过程**：模型 CoT 与中间猜测不宜直接持久化为长期记忆，避免误导后续决策与审计。

例如，“用户今天在上海出差”适合作为有时效的事件；“用户偏好中文回答”适合作为可更新的用户偏好。将两者同等永久保存会造成记忆污染。

### 2.3 热路径与后台路径

- **热路径**：任务恢复必需的检查点，以及 Agent 主动调用的 memory 工具，要求低延迟、可立即读回。
- **后台路径**：抽取、去重、实体归一、摘要与索引重建，通过队列或定时任务完成，不阻塞用户请求。
- **批处理**：把多条短消息缓冲到阈值、空闲超时或显式 flush 再统一处理，可降低抽取成本并减少画像抖动。
- **代价**：写入到可见之间存在延迟，属于最终一致；测试时要分别断言“写入成功”与“处理后可召回”。
- **幂等**：以命名空间、主体、字段与事件 ID 组成去重键，保证重试与乱序不产生重复记忆。
## 三、判定与写入

### 3.1 判定：是否值得长期保存

| 判定维度 | 要回答的问题 | 倾向不写入的情形 |
| --- | --- | --- |
| 稳定性 | 这条信息多久会变 | 一次性寒暄、临时上下文 |
| 重要性 | 未来任务是否真的会用到 | 与长期目标无关的细节 |
| 置信度 | 证据是否充分 | 单次推断、互相矛盾的片段 |
| 时效性 | 是否需要有效期 | 无法判断有效期的“现状”描述 |
| 隐私与权限 | 是否允许持久化、谁能读 | 凭证、密钥、身份证号等敏感信息 |
| 成本 | 存储与检索开销是否划算 | 可由外部系统实时查询的数据 |

最后一条尤其重要：能通过工具实时获取的数据（库存、工单状态、当前配置）应走查询而不是走记忆，否则记忆会持续过期并制造冲突。

### 3.2 写入动作：新增不是唯一选项

| 动作 | 触发条件 | 注意点 |
| --- | --- | --- |
| `ADD` | 新主体、新字段或新事件 | 需要去重键，避免重复堆积 |
| `UPDATE` | 同一字段出现新值 | 更新当前值并保留历史版本 |
| `MERGE` | 多条记忆语义重复 | 压缩为摘要或结构化字段，保留来源 |
| `INVALIDATE` | 事实过期或被推翻 | 标记失效而非物理删除，便于追溯 |
| `NOOP` | 已存在等价记忆 | 只刷新时间戳与强度，不新增记录 |

多数系统的自动抽取路径是**追加式**的：新事实被写入，旧事实不会自动消失，冲突被推迟到检索阶段处理。因此“修正旧记忆”必须作为显式操作存在，否则新旧事实会长期并存，表现为 Agent 一会儿说用户在北京、一会儿说在上海。

### 3.3 写入时必须落地的元数据

生命周期后续阶段全部依赖写入时的元数据：没有有效期就无法衰减，没有来源就无法裁决冲突，没有命名空间就无法隔离，没有版本就无法回滚。字段清单与治理控制面见[记忆架构](./2%20记忆架构.md)。

写入前后的最小检查：

1. 敏感信息与权限校验（写入前拦截，而不是写入后补救）；
2. 命名空间与作用域确定（用户 / 租户 / Agent / 会话 / 任务）；
3. 来源、证据与置信度标注；
4. 创建时间、事件时间与有效期设置；
5. 幂等键与版本号写入，便于重试与并发合并。

## 四、巩固与索引

巩固（consolidation）是把“写入的记录”变成“可高效检索的记忆”的阶段，通常在后台完成。

- **索引构建**：向量索引负责语义召回，关键词或 BM25 负责精确匹配，图索引负责实体与关系遍历；三者可以并存。
- **实体归一**：消歧同义实体、统一命名与单位，否则图会迅速积累重复节点与冲突关系。
- **分层压缩**：情节记忆 → 会话摘要 → 长期摘要，逐层减少数量、提高稳定性。
- **模式升级**：多次重复出现的做法可升级为程序性经验；反复被纠正的内容应降低置信度。
- **触发方式**：写入即建索引（低延迟）、批量后台（低成本）、定时或显式 consolidate（可控）。

一致性要求：写入成功不等于可检索。索引任务应有状态、可重试、可全量重建，并且删除操作必须同步清理正文、索引与派生摘要，避免出现“已删除仍被召回”。

## 五、检索、组装与使用

### 5.1 检索：相关性不等于可用性

检索一般先做硬约束过滤，再进行软排序：

```text
user / tenant / 权限过滤
  → 任务、实体、时间等元数据过滤
  → 向量、关键词或图检索
  → 重排、去重、冲突检测
  → 预算截断与上下文组装
```

排序可综合多个信号，而不是只看语义相似度：

```text
score = w1 × 语义相关性
      + w2 × 时间新鲜度 / 保留强度
      + w3 × 重要性
      + w4 × 来源置信度
      − w5 × 访问成本与风险
```

- **事实与偏好**：优先最新且置信度更高的版本；
- **情节记忆**：保留事件时间与发生顺序，时间有效性优先于相似度；
- **衰减函数**：保留强度的计算方式与参数校准见 [Ebbinghaus 遗忘曲线](./1%20公共知识/1%20Ebbinghaus遗忘曲线.md)。

### 5.2 组装：把记忆变成可用上下文

召回结果进入模型前还要经过组装：设置 token 预算、按类型套用模板、标注来源与时间，让模型能判断每条信息的可信度。冲突不应被静默裁决——要么使用最新的高置信度版本，要么显式标注“待确认”。组装与降级策略见[记忆架构](./2%20记忆架构.md)。

### 5.3 使用即反馈

读取侧是唯一能验证记忆价值的地方，应把使用情况回写到维护侧：

| 使用结果 | 反馈动作 |
| --- | --- |
| 被采纳并推动任务成功 | 提升强度与置信度 |
| 被用户或工具纠正 | 降权、转入待确认或触发更新 |
| 被召回但未使用 | 记录为低价值命中，进入衰减候选 |
| 长期未被召回 | 进入归档评估 |

这也是“间隔重复”在 Agent 中的对应物：成功检索会强化记忆，长期不用则自然褪色。没有反馈回路的记忆系统无法区分“有用”和“只是存在”。
## 六、演化与冲突处理

记忆系统最难的部分不是写入，而是避免“越记越错”。

### 6.1 冲突类型与处理策略

| 冲突类型 | 示例 | 推荐处理 |
| --- | --- | --- |
| 时间演进型 | 住在北京 → 住在上海 | 更新当前值，旧值转为带有效期的历史 |
| 来源矛盾型 | 用户自述与工具返回不一致 | 按来源可信度裁决，必要时向用户确认 |
| 粒度差异型 | “回答要简洁”与“回答要带示例” | 合并为更完整的偏好描述 |
| 推断错误型 | 模型误判用户角色或意图 | 标记失效，保留纠错记录以防重犯 |
| 主体混淆型 | A 用户的偏好被写到 B | 立即隔离或删除，并触发审计 |

处理原则：**当前值唯一，历史可追溯**。不要为了让回答“看起来一致”而物理删除旧事实，历史版本本身就是解释和回滚的依据。

### 6.2 版本与时间语义

- **双时间轴**：区分事件发生时间（valid time）与系统写入时间（transaction time），前者用于判断事实新旧，后者用于审计。
- **有效区间**：关系与状态用“从何时起成立、到何时失效”表达，而不是直接删边，这样“去年谁负责这个项目”才可回答。
- **乱序到达**：晚到的旧事实不应覆盖新事实，比较依据是事件时间而不是写入顺序。
- **待确认队列**：证据不足或冲突未裁决时进入待确认状态，检索时可召回但必须标注不确定性。

### 6.3 合并与去重

- 语义重复的记忆压缩为更稳定的摘要或结构化字段；
- 合并时保留全部来源指针，避免摘要变成无证据的断言；
- 合并应可逆或至少可重建：保留原始事件，必要时能重新抽取。

## 七、衰减、归档与遗忘

### 7.1 阶梯式处置

遗忘不是一个动作，而是一组按成本与风险递进的手段：

```text
降权（排序下调） → 冷存储（迁出热索引） → 摘要合并（多条压成一条） → 删除（正文 + 索引 + 派生摘要）
```

优先降权而不是删除：降权可逆，删除不可逆。只有合规要求或确认错误时才走到最后一步。

### 7.2 衰减参数应按类型区分

| 记忆类型 | 衰减速度 | 触发遗忘的条件 |
| --- | --- | --- |
| 任务状态与工作记忆 | 极快 | 任务结束或会话关闭 |
| 时效事件（行程、临时状态） | 快 | 超过有效期且无后续引用 |
| 情节记忆 | 中 | 长期未命中且已被摘要覆盖 |
| 用户偏好与稳定事实 | 慢 | 被新事实取代或用户要求删除 |
| 程序性经验 | 慢 | 被反例反复推翻 |

用同一套衰减参数处理所有类型，会导致稳定偏好被误删、临时状态长期驻留。

### 7.3 遗忘的三类正当理由

- **质量**：噪声与过期信息会污染召回，让正确记忆被淹没；
- **成本**：存储、索引与上下文 token 都随记忆数量线性上升；
- **合规**：删除权、保留期限、租户注销与敏感信息最小化要求。

删除必须同步清理正文、向量与图索引、派生摘要及缓存，并保留删除审计（谁、何时、依据什么）。

“遗忘”不是故障，而是维持检索质量、成本和隐私边界的必要能力。

## 八、不同类型记忆的生命周期差异

| 记忆类型 | 写入时机 | 有效期 | 更新方式 | 结束方式 |
| --- | --- | --- | --- | --- |
| 工作记忆 / scratchpad | 任务执行过程中 | 任务内 | 直接覆盖 | 任务结束即释放 |
| 任务状态与检查点 | 步骤完成时 | 任务或会话 | 幂等覆盖 | 任务归档 |
| 情节记忆 | 回合或事件结束 | 中期 | 只追加不修改 | 摘要化后转冷存储 |
| 语义事实与偏好 | 判定通过后 | 长期 | 版本化更新 | 被新事实取代或用户删除 |
| 关系与图记忆 | 实体识别后 | 带有效区间 | 边失效标记 | 区间闭合后归档 |
| 程序性经验 | 多次验证后 | 长期 | 置信度调整 | 被反例推翻 |

同一套流水线服务不同生命周期，靠的是元数据里的类型、有效期与命名空间，而不是为每类记忆单独建一套系统。

## 九、常见失效模式与对策

| 失效模式 | 表现 | 根因 | 对策 |
| --- | --- | --- | --- |
| 记忆污染 | 错误信息被后续任务反复引用 | 抽取阶段把推测当事实 | 来源分级、置信度门槛、待确认状态 |
| 错误固化 | 同一错误在多个任务中重现 | 缺少反馈回路与纠错入口 | 使用反馈降权、显式 update / delete |
| 越记越多 | 召回质量随记忆量上升而下降 | 只增不减、无衰减策略 | 阶梯式处置、定期巩固与摘要 |
| 过期召回 | 用旧状态回答当前问题 | 无有效期或排序忽略时间 | 有效期字段、时间新鲜度参与排序 |
| 越权泄漏 | 返回其他用户或租户的记忆 | 检索前未做主体过滤 | 命名空间硬过滤、权限前置校验 |
| 写入成功不可检索 | 记忆存在但召回不到 | 索引任务失败或未触发 | 索引状态可观测、支持重建 |
| 已删除仍被召回 | 删除请求未生效 | 索引与派生摘要未同步清理 | 删除级联到全部副本并留审计 |
| 反复澄清 | Agent 记不住已确认的信息 | 判定门槛过高或命名空间错配 | 检查抽取规则与作用域配置 |

## 十、可观测性与验收

### 10.1 分阶段指标

| 阶段 | 建议指标 |
| --- | --- |
| 捕获与抽取 | 候选记忆数量、抽取精确率、人工接受率 |
| 判定与写入 | 写入通过率、拒绝原因分布、重复写入率 |
| 巩固与索引 | 索引延迟、索引失败率、重建耗时、合并压缩比 |
| 检索 | Recall@K、MRR、过期记忆误召回率、权限拦截次数 |
| 组装与使用 | 上下文 token 占比、召回未使用比例、降级次数 |
| 演化与遗忘 | 冲突数量与解决正确率、失效与删除数量、归档占比 |
| 端到端 | 任务成功率、重复澄清次数、延迟与成本 |

系统级可靠性与可观测性要求见[记忆架构](./2%20记忆架构.md)，指标定义与测试集设计见[基准与评测](./20%20实践与评测/2%20基准与评测.md)。

### 10.2 生命周期验收清单

- 一条记忆从产生到删除的每一步都可追溯（来源、时间、操作者、依据）；
- 每条标准答案都标注主体、时间范围、证据来源与是否允许写入长期记忆；
- 分别验证“写入成功”与“巩固后可召回”，不混为一个断言；
- 验证过期事实不会主导回答，新事实能正确取代旧事实；
- 验证删除后正文、索引与派生摘要均不可召回；
- 验证检索失败或权限不足时返回空记忆上下文，Agent 仍能完成当前任务。

## 十一、开源实现对照

不同方案覆盖的生命周期阶段并不相同，选型时应看它把哪些阶段做成了产品能力：

| 方案 | 生命周期侧重 | 代表机制 |
| --- | --- | --- |
| [Memobase](./10%20开源方案/2%20Memobase/2%20Memobase原理.md) | 捕获到沉淀 | blob → buffer → flush，产出 profile 与 event |
| [Mem0](./10%20开源方案/3%20Mem0/2%20Mem0原理.md) | 抽取、写入与检索 | 追加式自动写入 + 显式 update / delete，多信号混合检索 |
| [MemGPT / Letta](./10%20开源方案/4%20MemGPT/2%20MemGPT与Letta原理.md) | 组装与归档 | 主上下文与归档记忆之间换页，过期内容迁出压缩 |
| [Graphiti](./10%20开源方案/5%20Graphiti/2%20Graphiti原理.md) | 演化与时间语义 | episode 增量写入时序图，关系带有效区间 |
| [LangMem](./10%20开源方案/6%20LangMem/2%20LangMem原理.md) | 热路径与后台路径 | memory tools 即时读写 + background manager 异步整理 |
| [AgentMemory](./10%20开源方案/8%20AgentMemory/2%20AgentMemory原理.md) | 维护侧全流程 | Decay → Forget → Consolidate → Update 的周期维护 |

没有任何一个方案能替代完整的生命周期设计：抽取质量、判定门槛、冲突策略与遗忘节奏，最终都要结合自身的任务形态和数据分布来校准。
