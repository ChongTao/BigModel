# 大模型生产韧性

韧性是指系统在模型超时、供应商限流、工具失败、流量突增或配置错误等情况下，仍能维持核心服务、限制影响范围并可恢复的能力。它要求在设计阶段明确哪些体验必须保住，哪些功能可以降级或延后。

## 设计目标

| 目标 | 说明 | 示例 |
| --- | --- | --- |
| 隔离 | 单一租户、模型或依赖故障不扩散 | 按租户和优先级设并发池 |
| 降级 | 依赖不可用时仍提供有用结果 | 返回检索摘要或异步结果 |
| 可恢复 | 失败任务可重试、可重放、可追踪 | 队列持久化与幂等键 |
| 可观测 | 故障能快速定位和量化影响 | 统一追踪、告警和运行手册 |
| 可演练 | 恢复流程在事故前已验证 | 定期故障注入演练 |

## 常见故障与策略

| 故障 | 首选应对 | 注意事项 |
| --- | --- | --- |
| 模型超时或短暂错误 | 有限重试、切换备用模型 | 仅对幂等请求重试，使用退避和抖动 |
| 供应商限流或配额耗尽 | 排队、限流、降级、分流 | 保护交互与高价值请求 |
| 工具或检索依赖不可用 | 返回已知信息、部分结果或异步任务 | 明确告知结果范围，避免编造 |
| 突发流量 | 背压、优先级队列、并发隔离 | 拒绝低优先级请求优于拖垮全部服务 |
| 发布或配置错误 | 快速回滚、关闭开关 | 版本化 Prompt、路由和策略 |
| 长链路工作流中断 | 检查点、幂等步骤、可恢复状态机 | 不从头重复高成本步骤 |

## 超时、重试与熔断

### 超时

为网关、模型、工具、检索和工作流设置独立的时间预算，整体 deadline 应向下游传播。超时后取消无用工作，避免请求已经返回而后台仍持续消耗资源。

### 重试

只重试瞬时错误，如网络短暂失败或可恢复限流；不要对策略拒绝、参数错误或持续性故障盲目重试。限制最大次数，采用指数退避和随机抖动。对有副作用的工具调用，必须使用幂等键或先查询执行状态。

### 熔断与舱壁

当某模型或工具持续失败、延迟异常或费用异常时，熔断器应暂时停止向其发送新流量，并周期性探测恢复情况。使用“舱壁”隔离不同模型、租户、任务类型和优先级的连接、并发和队列，防止一个热点耗尽全局资源。

## 多模型与多路径

备用路径不等于无条件切换。为每类任务预先定义：主模型、可接受的备用模型、质量差异、最大切换时延和回退策略。重要场景应通过离线评测确认备用模型能够满足最低质量线。

可以按风险设计多级降级：

1. 正常：主模型 + 完整工具链。
2. 轻度降级：关闭非关键工具或缩短上下文。
3. 中度降级：切换备用模型、返回简短答案或仅使用检索结果。
4. 重度降级：排队异步处理，或明确提示暂不可用。

降级状态需要对用户和运营可见，不能把不完整结果伪装成完整答案。

## 异步任务与数据一致性

耗时任务使用持久化队列和可查询的任务状态。每个任务应具备唯一标识、幂等键、输入版本、执行尝试次数、检查点和结果版本。消费者需能安全重放消息，并通过死信队列收集超过重试上限的失败任务。

对于涉及写入的工具操作，先定义业务补偿而不是假定可以事务回滚。将模型生成的建议、审批决定和实际执行分开保存，确保可审计和人工介入。

## 运行与演练

- 为模型不可用、限流、工具超时、缓存异常和流量尖峰编写运行手册。
- 定期演练故障注入，验证告警、切换、降级、恢复和沟通流程。
- 记录恢复时间、受影响请求、降级比例和数据补偿结果，持续改进 SLO。
- 发布前验证开关、回滚、备用模型和容量配额，不在事故中首次启用。

韧性并非无限堆叠备用资源，而是以清晰的优先级、可验证的降级路径和可恢复的数据流程，保护最关键的业务承诺。
